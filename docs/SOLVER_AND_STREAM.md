# Решатель (переносимый пакет), обязательный классификатор, слияние сигналов, replay

Изменения 5-й итерации. Предыдущие: `AUDIT_AND_CHANGES.md`, `REALTIME.md`, `OPERATIONS.md`.

## 1. Решатель `*.sdsolver.zip`

Полный пайплайн одним архивом для передачи на другое устройство.

```bash
sd solver pack final --name final_v1 --with-weights --with-dataset --run <id_оценки>   # → outputs/solvers/final_v1.sdsolver.zip
sd solver inspect final_v1.sdsolver.zip        # метаданные и проверка sha256
sd solver install final_v1.sdsolver.zip        # безопасная двухфазная установка в models/ и labels/
sd solver check   final_v1 --mode live         # допустим ли режим на этом устройстве
sd solver list
sd eval --solver final_v1 ... | python -m sd.run --solver final_v1 ... | sd replay clip.mp4 --solver final_v1
```

В архиве: `solver.json` (метаданные, схема 1), `profile.yaml`, пакеты классификатора/фото-модели, по желанию веса (`--with-weights`) и набор разметки
(`--with-dataset`: `events_gt.csv`, `cycle_labels.csv`, индекс клипов). Все пути переносимые (`$DATA/…`), у каждого файла sha256.

**Метаданные для автоопределения архитектуры** (`solver.json → architecture`): режим (`classifier`, `classifier+fusion`, `classifier+evidence+photo+vlm` …),
стадии (поза → трекинг → автомат циклов → признаки → классификатор → слияние → правила регламента), модель каждой стадии с sha256 весов,
группы признаков и список `features` классификатора, оценка ресурсов (пик/последовательная память, порядок величин), допустимые режимы `offline/replay/live`,
оценка качества на момент упаковки (F1, порог, число клипов), отпечаток профиля. По ним `sd solver check` и UI («Модели → Решатель») решают, годится ли решатель
для режима: например `live` запрещён, если классификатору нужны признаки предмета/фото (в настоящем потоке исходного файла нет).

**Безопасность установки:** имена членов архива проверяются (`_safe_member`: без абсолютных путей, `..`, ссылок), sha256 сверяются до записи,
установка идёт во временный каталог и переносится целиком; существующее не перезаписывается без `--overwrite`.

## 2. Классификатор цикла обязателен

Без классификатора оценка цикла — эвристика по длительности паузы, она не отличает питьё и телефон от курения. Поэтому:

* `Profile.classifier_problem()` — единая проверка; её делают `pipeline.recognize` (`ClassifierRequired`), `sd eval`, `sd.run`, `sd monitor`, `sd replay`, страницы «Оценка»/«Поток».
* Эвристика только явно: `options.allow_heuristic: true` / `profiles.heuristic_profile()` (отладка и тесты).
* В «Оценке» выбор классификатора — отдельный блок **перед** остальными моделями; `--classifier <имя>` в CLI подменяет выбранный в профиле.

## 3. VLM и другие признаки — надстройка, вектор признаков не меняется

`options.fusion` (`src/sd/fusion.py`): поправка к **логиту** оценки классификатора по сигналам `vlm_yesno`, `photo_p_mean`, `obj_any_max_conf`:
`logit' = logit + clip(Σ w_i·(s_i − ref_i), ±clip_logit)`. Вес 0 или нет сигнала — оценка прежняя (NaN-безопасно). В таблице остаются `score_base` и `fusion_*`.
Пакет классификатора и его `features` не затрагиваются. Веса подбирайте на валидации (страница «Эксперименты» → варианты профиля, ключ `fusion`). Каскад «серая зона → VLM» (`cycle_bundle_full`) по-прежнему доступен.

## 4. Replay — аналог real-time по видео

`sd replay clip.mp4 -p stream_cpu6 [--speed 1] [--gt] [--render]` и страница **«Поток»**. Файл идёт через тот же `StreamEngine`, что и камеры
(скользящий буфер 90 с, тот же автомат и правила).

* **Без эталона** («просто решение модели»): тревоги в момент срабатывания (время потока, начало события, ID, причина, уверенность, задержка), `events.csv`, `alerts.csv`, `log.csv`, `summary.json`.
* **С эталоном** (`labels/events_gt.csv`, «с разметкой и выводом»): TP/FP/FN, precision/recall/F1 по протоколу организаторов и **задержка тревоги** (от начала курения по разметке до тревоги).
* `--render` — `overlay.mp4`: рамки людей, красный баннер тревоги, метка «GT: курение», время.
* **Пропускная способность:** `rt_factor` = секунд видео / секунд вычислений; ≥ 1 — справляется, число камер ≈ целая часть; < 1 — отстаёт (снизьте `video.process_fps`, `pose.imgsz`, отключите уточнение).
* Результаты: `outputs/replay/<время>_<клип>/`.

Ограничение: в настоящем потоке (`monitor`) доступны только быстрые признаки (поза, пауза, ритм). Классификатор с признаками предмета/фото/VLM допустим в `replay` и `offline`
(исходный файл доступен), для `live` такой решатель отклоняется проверкой, а не работает молча хуже.

## 5. Профили под два ПК

| ПК | Профиль | Поза | Классификатор |
|---|---|---|---|
| 16 ГБ ОЗУ + 4 ГБ GPU | `stream_gpu4` (поток), `laptop_gpu4` (offline/replay) | YOLO26s@1280 CUDA + RTMPose-s, 8 к/с | `cycle_fast` / `cycle_mvp` |
| 6 ГБ ОЗУ, без GPU | `stream_cpu6` | YOLO26n@960 OpenVINO CPU, без уточнения, 6 к/с | `cycle_fast` |

**Не измерены на этих машинах.** Перед использованием: `sd replay <клип> -p <профиль>` — смотреть `rt_factor` (нужен запас ≥ 1.5) и F1 при `--gt`.
Тест `tests/test_shipped_profiles.py` проверяет, что все поставляемые профили загружаются и имеют классификатор.
