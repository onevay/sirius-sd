## 0. Главный принцип

На 23 эпизодах одна ошибка двигает F1 на 4–8 пунктов. Поэтому единица прогресса в этом проекте — не «F1 стал выше», а **«улучшение подтверждено на данных, которых модель и разработчик не видели, и вышло за доверительный интервал»**.

Порядок работы всегда один:

```
данные → эталон (метки) → базовая линия → гипотеза (одна) → эксперимент → честная оценка → решение → запись
```

Три вещи нельзя нарушать, они объясняют большинство ошибок раздела 10:
1. **Модель не оценивается на том, на чём училась** (утечка).
2. **Порог не подбирается на отложенной выборке.**
3. **Сравнивать можно только прогоны на одной и той же разметке** (`gt_fingerprint`).

## 2. Данные: что и как собирать

### 2.1. Что нужно модели

Качество упирается в **разнообразие**, а не в количество часов. Покрытие, которое нужно получить (и вести таблицей):

| измерение | значения | почему важно |
|---|---|---|
| расстояние (рост человека, px) | 80–120, 120–200, 200–400, > 400 | реальные камеры чаще дальние, а в выборке медиана 377 px |
| ракурс | сверху, спереди, сбоку, со спины | рот и рука видны по-разному |
| свет | день, сумерки, ночь, ИК | детектор предмета и поза деградируют |
| плотность | один человек, 2–5, толпа | смена ID, перекрытия |
| **позитивы** | сигарета, вейп, у рта с паузой, разные руки | — |
| **сложные негативы** | питьё, телефон у уха, еда, касание лица, жесты руками, жвачка, шарф | именно на них ошибается классификатор |
| площадки | не менее 3 разных | чтобы оценка не мерила узнавание сцены |

Теги сценариев P01–P08 (позитивы) и N01–N08 (негативы) описаны в [PLATFORM_GUIDE.md](PLATFORM_GUIDE.md); в метках они пока не проставлены.

### 2.2. Сколько

Ориентир (рекомендация, не измерено):

| назначение | минимум | сейчас |
|---|---|---|
| эталон событий | ≥ 40 эпизодов курения, ≥ 40 негативных интервалов | 25 POSITIVE, 11 NEGATIVE в `events_gt.csv` |
| циклы для обучения | ≥ 400 размеченных | 217 (103 затяжки) |
| **отложенная выборка** | ≥ 12 позитивов с других площадок или дней | нет |

Правило объёма: число признаков классификатора не больше примерно одной десятой числа положительных циклов. Поэтому на ≈ 100 затяжках побеждает набор из 6 признаков, а 42 признака переобучаются.

### 2.3. Как собирать

1. Фрагменты 1–5 минут из реальных записей, **без пересечения по времени**. Имя файла несёт камеру и дату: так проще сгруппировать для оценки.
2. Сначала смотреть, потом брать: клип без людей у рта не помогает. Подбор окон — `sd windows`, статистика роста людей — `sd eda`.
3. Не брать подряд соседние фрагменты одной сцены в обучение и оценку одновременно. Группа оценки — сцена или камера, а не клип (`sd oof-eval --by-scene`).
4. Собственные записи складывать в `data/custom/` (или отдельную папку), открытые — через `sd fetch-videos`; внешние данные лежат в `data_external/` и в git не попадают.
5. **Данные площадки обрабатываются только локально.** В облачные сервисы, внешние VLM и репозиторий кадры не отправляются.
6. Перед разметкой — Dev Studio, «Данные → Каталог» и «Проблемы»: дубликаты, клипы без метки, противоречия папки и разметки.

Внешние датасеты проверены и не дали пользы: HMDB51 (рука у лица в 13 % клипов «курение», AUC 0.51), фото-датасеты не переносятся на кропы камер (AUC 0.96–0.998 на фото, 0.54–0.65 на кропах). Не тратьте время на них повторно.

## 3. Разметка

### 3.1. Два слоя

| слой | файл | что внутри | кто использует |
|---|---|---|---|
| **жесты** | `labels/review/gesture_gt.csv` | окна: затяжка, нет жеста, неясно, касание лица, питьё, телефон | эталон событий строится из него; обучение классификатора |
| **события** | `labels/events_gt.csv` | POSITIVE / NEGATIVE / IGNORE, интервал, рамка, `peak_sec` | оценка Event F1 |
| метки циклов | `labels/cycle_labels.csv` | `smoke`, `drink`, `phone`, `eat`, `touch_face`, `other_neg`, `ignore`, `unsure` (формат — `labels/README.md`) | обучение; переживает смену порогов автомата |

### 3.2. Правила разметки (инструкция разметчику — приложение B)

- **POSITIVE** — человек курит: сигарета или вейп, подряд затяжки; интервал от подъёма руки первой затяжки до отведения последней.
- **NEGATIVE** — сознательно подтверждённое отсутствие курения при похожих жестах (питьё, телефон). Нужны и они: без них нечем считать ложные тревоги.
- **IGNORE** — нельзя утверждать: человек ниже 80 px, закрыт, жест неясен. IGNORE не штрафуется оценкой. **Нельзя сваливать в IGNORE «сложные» случаи ради красивой метрики.**
- Допуск оценки по времени ±3 с; ставить границы с точностью ~1 с, не в кадр.
- Метка не по папке, а по содержимому: слабая метка папки уже ошибалась (клипы `smoking_noyabrsk_2/3` в «лжекурении» содержат 6 эпизодов).

### 3.3. Процесс

1. Размечать в Dev Studio: «Задачи → Разметка событий» и «Метки жестов» (плеер с кандидатами циклов). В боковой панели указано «Кто работает».
2. Эталон событий из жестов: `sd gt-from-gestures --labeler <имя>`.
3. **Перед любой массовой правкой — снимок версии** (`sd labels snapshot …`; Dev Studio делает сам). Откат — `sd labels restore` или «Данные → Версии разметки».
4. Проверка: «Данные → Проблемы» и «Валидация → Анализ кэша» (правила слабых мест: клипы, где модель и метка расходятся).
5. **Второй разметчик** независимо размечает 10–15 клипов; считается согласие (κ Коэна). Приёмка: κ ≥ 0.7, иначе уточняются определения, а не размечается дальше. Сейчас второго разметчика нет — это главное ограничение доверия к эталону.
6. Спорные случаи оформлять как `unsure`/`ignore`, а не угадывать. Они в обучение не берутся.

### 3.4. Активное обучение

Не размечайте клипы подряд. Приоритет такой:
1. Ошибки текущей модели (FP и FN из «Аналитика → Ошибки и порог») — именно они информативны.
2. Циклы с оценкой около порога (серая зона): размечать их выгоднее всего.
3. Решения оператора: подтверждённые → POSITIVE, ложные → **жёсткие негативы** (`sd feedback-export`, «Данные → Обратная связь оператора»). Экспорт не создаёт дубликатов.
4. Новые площадки и условия, где качество не измерено.

## 4. Метрики и честная оценка

### 4.1. Event F1

Протокол организаторов: событие найдено, если интервалы совпадают с допуском ±3 с и рамки в момент пика с IoU ≥ 0.30; сопоставление один к одному; IGNORE не штрафуется. Доверительный интервал — bootstrap по клипам. Реализация — `evaluation.py`; это копия протокола, официального валидатора нет.

Смотреть всегда вместе: F1, precision, recall, TP/FP/FN, **число ложных тревог в час** (для оператора это главная цифра), задержку тревоги.

### 4.2. Три уровня оценки

| уровень | что это | что значит |
|---|---|---|
| 1. F1 на клипах обучения | обычный прогон `sd eval` | **оптимистично**; годится для отладки механики |
| 2. Вложенная oof-оценка | `sd oof-eval`: оценка цикла дана моделью, не видевшей это видео; порог подбирается вложенно | честная оценка на имеющихся клипах; используется для выбора набора признаков и модели |
| 3. Отложенная выборка | клипы, которых не видели ни модель, ни разработчик | единственная гарантия; смотрится один раз на релиз |

Утечка обучения контролируется автоматически: `bundle.leak` показывает пересечение видео обучения и оценки. Dev Studio выводит предупреждение в чек-листе запуска, в результате и PDF; ворота выпуска не пропускают такой пакет; на роли `hidden` оценка с утечкой отказывает.

### 4.3. Когда улучшение настоящее

Принимайте изменение, только если одновременно:
1. Оно проверено на уровне 2 или 3, не на 1.
2. Парное сравнение с базовой линией на общих клипах (`Аналитика → Влияние параметров → Парное сравнение` или `sweep.compare_saved`) показывает выигрыш, а не просто разницу средних. Доверительные интервалы прогонов перекрываются почти всегда — этого недостаточно ни для вывода «лучше», ни «хуже».
3. Выигрыш не получен за счёт одного клипа (смотреть «Аналитика → По клипам»).
4. Цена приемлема: скорость (`rt_factor`) и память не вышли за целевое железо.
5. Нет роста ложных тревог в час.

### 4.4. Чего нельзя

- Подбирать порог события на отложенной выборке (порог фиксируется до неё: `role=hidden`, `policy=fixed`).
- Менять правила регламента ради метрики.
- Смотреть на отложенную выборку чаще одного раза за релиз: после этого она становится обычной оценочной.
- Переобучать классификатор на клипах, по которым измеряете качество, и сообщать результат как итог.

## 5. Выбор параметров по этапам

Все 99 параметров описаны в `configs/default.yaml` (комментарий в строке) и видны в «Конструкторе» с ценой правки. Ниже — те, что реально влияют на результат.

### 5.1. Поза и трекинг (цена: пересчёт позы — самое долгое)

| параметр | значения | замеры и правила |
|---|---|---|
| `video.process_fps` | 5 / 10 | 10 к/с: +8 п.п. найденных затяжек и F1 0.829 против 0.780 (интервалы перекрываются), время ×2. 5 — реальное время, 10 — режим качества |
| `pose.imgsz` | 960 / 1280 / 1600 | **главный рычаг для дальних людей**. Размер модели (s/m/x) качество не поднял |
| `pose.weights`, `pose.runtime`, `pose.device` | yolo26n, openvino, intel:gpu | выбор по железу; профиль под другое железо проверяйте в «Конструкторе» (проверка устройств) |
| `pose.refine.*` | rtmpose-s, `gate_s` | уточнение только при руке у лица экономит время; полное уточнение по всем замедляет сквозную скорость примерно до 8 к/с |
| `tracking.tracker`, `track_buffer_sec`, `stitch.*` | botsort, 3 с | цель — меньше смен ID; измерять на плотных сценах (1.29 трека на человека на 19 окнах) |
| `video.min_person_height_px` | 80 | регламент, не менять |

### 5.2. Ряд и автомат циклов (цена: циклы и признаки по ним заново)

| параметр | значение | замеры и правила |
|---|---|---|
| `cycles.th_in` / `th_out` | 0.65 / 0.90 | значения руководства 0.35/0.55 находят 2 из 12 затяжек; плато th_in 0.50–0.80 и th_out 0.70–1.15 — 11 из 12. Брать **центр плато**; перепроверять через `sd calibrate` и «Аналитика → Ошибки и порог» при росте данных |
| `cycles.hold_min_sec`, `hold_max_sec`, `hold_cap_sec` | 0.5 / 5 / 12 | регламент задаёт паузу 0.5–5 с; удержания дольше остаются кандидатами (`emit_long_hold`), решает классификатор |
| `features.mouth_offset` | 0.35 | положение «рта» относительно носа и плеч |
| `features.median_sec`, `smooth_sec` | 0.3 / 0.4 | чем сильнее сглаживание, тем позже тревога и меньше шума |

Как подбирать: `sd calibrate` перебирает пороги по готовым запускам без пересчёта позы. Критерий — доля найденных размеченных затяжек при приемлемом числе кандидатов (кандидатов много — нагрузка на классификатор растёт).

### 5.3. Признаки цикла

| вариант | цена | ценность |
|---|---|---|
| быстрые (поза, ритм, пауза) | миллисекунды | AUC цикла 0.65; единственные доступны в live |
| предмет у рта (детекторы на кропе) | ≈ 1.8 с на цикл на iGPU | главный сигнал, AUC одиночного признака ≈ 0.88 |
| zero-shot CLIP по кропу рта | ≈ 0.7 с на цикл | +помогает отличать питьё и телефон |
| VLM (Ollama, Qwen3.5-2B) | ≈ 11 с на цикл | +0.03–0.04 F1, в пределах шума; только для серой зоны (`options.vlm_mode: grey`, `vlm.grey_zone`) |
| видео-модели (X-CLIP, VideoMAE) | ≈ 6 с на цикл | не использовать: выучивают сцену, VideoMAE под CC-BY-NC |

### 5.4. Классификатор (цена: секунды)

- Набор признаков выбирается **по вложенной oof-оценке**, а не по обучающей:
  `sd oof-eval --sets fast,obj_hold,obj_hold_zsd,obj_hold_vlm --by-scene`.
- Короткие наборы лучше длинных. Измерено: `obj_hold_zsd` (6 признаков) — вложенный F1 0.74–0.76; `full` (42 признака) — 0.57–0.67.
- Члены ансамбля `--kinds lr,gb,nn`; при малых данных простая логистическая регрессия не хуже, чем бустинг.
- Диагностика переобучения обязательна перед обучением пакета: `sd clf diagnose` — разрыв train−oof, перестановка меток (должна дать AUC ≈ 0.5), кривая обучения. Разрыв больше нескольких пунктов — признаков слишком много.
- Калибровка (изотоническая) входит в пакет. Смеси оценок и калибровка уверенности эпизода вложенный F1 не подняли.

### 5.5. Правила события (цена: секунды, но фиксируются до отложенной выборки)

| параметр | значение |
|---|---|
| `events.cycle_th` | 0.4 (в `mvp`; в `default.yaml` 0.5) |
| `events.confidence_threshold` | 0.55 |
| `events.merge_gap_sec`, `window_sec` | 15 с, 20 с (регламент) |
| `events.object_k` из `object_n` | 3 из 5 — «предмет устойчиво виден» |

Порог подбирается на кривой «F1 против порога» (`Аналитика → Ошибки и порог`): берётся **плато**, а не пик. Политика `plateau` по умолчанию устойчивее `best`.

### 5.6. Метод подбора

1. Идти по цене: сначала секундные параметры (пороги, правила, классификатор), потом минутные (признаки, фото, детекторы), и только потом дорогие (вход позы, fps, модели).
2. **Один параметр за раз.** Если менялось два, вывод не атрибутируется.
3. Грубая сетка → тонкая: «Конструктор → Серия вариантов» (CLI `sd variants`), затем «Аналитика → Влияние параметров» (графики и контролируемые пары: все остальные параметры и разметка одинаковы).
4. Цену правки показывает «Конструктор» (`arch.impact`): правка позы пересчитывает всё, правка порога — секунды. Поэтому дорогие эксперименты откладывайте, пока не исчерпаны дешёвые.
5. Не подгоняйте параметры под 31 клип: если выигрыш виден только на одном-двух клипах, это шум.

## 6. Эксперименты: методика

### 6.1. Цикл эксперимента

1. **Гипотеза в одну фразу:** «вход позы 1280 найдёт больше затяжек у людей 100–150 px без потери скорости ниже 1×».
2. **Изменение:** вариант профиля в «Конструкторе» (или `-s ключ=значение`). Менять одну вещь.
3. **Ожидание:** какую метрику и на сколько. Это защищает от подгонки задним числом.
4. **Прогон:** «Конструктор → Оценить» или «Валидация → Запуск». Чек-лист проверит утечку, устройство, кэш.
5. **Журнал:** «Аналитика → Журнал» — тег подхода (`pose-1280`, `clf-short`), заметка с выводом, закрепить базовую линию.
6. **Сравнение:** «Аналитика → Сравнение подходов», «По клипам», парное сравнение с базой.
7. **Решение:** принять, отвергнуть, повторить на уровне 2/3. Результат записать, **включая отрицательные** — они экономят время (см. приложение А в REPORT).

### 6.2. Дисциплина

- Все сравнения на одной разметке: колонка `gt_fingerprint` в журнале; фильтр по ней в «Аналитике». Прогоны на разной разметке не сравнивать.
- Тег и заметка к каждому прогону, который что-то доказывает; безымянные прогоны через неделю не расшифровать.
- Базовая линия закреплена и пересчитывается при каждом изменении эталона.
- Не перезаписывать профили: «Сохранить профиль» требует подтверждения; рабочий `mvp` не трогайте, делайте копию.
- Полный воспроизводимый след: профиль, отпечаток, git, зерно (`project.seed: 42`), версия меток.

### 6.3. Диагностика, когда качество не растёт

| симптом | вероятная причина | проверка |
|---|---|---|
| train высокий, oof низкий | переобучение | `sd clf diagnose`: разрыв, перестановка меток; сократить набор признаков |
| F1 прыгает между близкими конфигурациями | шум эталона | доверительные интервалы; парное сравнение; больше данных |
| FN: затяжка не найдена автоматом | позы/автомат | «Ошибки и порог»: причина «нет цикла»; пороги, вход позы, fps |
| FN: цикл есть, оценка ниже порога | классификатор | признаки цикла, порог, обучающие данные для таких условий |
| FP: питьё и телефон | мало жёстких негативов | активное обучение, признаки предмета и CLIP |
| FP/FN вокруг смены ID | трекинг | `tracking.*`, склейка |
| на одной камере хуже | другой масштаб/ракурс | таблица «клип × подход», рост людей (`sd eda`) |

### 6.4. Что уже пробовали (не повторять без новой идеи)

- Тяжёлые модели позы s/m/x: больше затяжек не нашли.
- Фото-классификатор на открытых фото: на кропах камер не работает.
- Видео-модели X-CLIP и VideoMAE: выучивают сцену.
- Дым как признак: простые признаки 0.48–0.64.
- Калибровка уверенности эпизода и смеси оценок: вложенный F1 не растёт.
- Длинные списки признаков (`full`, 42): хуже коротких.
- VLM: плюс в пределах шума при цене 11 с на цикл.

## 8. Бэклог улучшений

Приоритет — по отдаче на риск. Оценки выигрыша — **гипотезы**, подлежащие проверке по критерию успеха.

| # | идея | ожидаемый эффект | цена | риск | критерий успеха |
|---|---|---|---|---|---|
| 1 | Отложенная выборка и второй разметчик | честная цифра для заказчика | 1 нед. разметки | низкий | κ ≥ 0.7; ≥ 12 позитивов вне обучения |
| 2 | Записи дальних камер + лестница на них | знание реального качества, выбор входа позы | запрос данных у заказчика | данных может не быть | полнота при 80–200 px измерена |
| 3 | Вход позы 1280–1600, ROI, тайлинг для дальних | у дальних людей до 15 из 16 затяжек (на имитации) | ×2–3 времени на кадр | не успевает в реальном времени | `rt_factor ≥ 1.5` на целевом ПК |
| 4 | Переобучение без отложенной выборки, короткий набор признаков | снять утечку, честный релиз | 2–3 дня | падение метрики до реальной | ворота выпуска пройдены |
| 5 | Дообучение детектора предмета на кропах своих камер | поднять главный сигнал (сейчас цена ошибки максимальна) | разметка кропов + обучение | переобучение на малой выборке | AUC предмета на отложенных кропах выше |
| 6 | Онлайн-склейка треков | меньше пар «1 TP + 1 FP» | 1–2 нед. | регрессия на плотных сценах | совпадение replay и offline по событиям |
| 7 | Признаки предмета в потоке (кропы из `FrameRing`) | live приближается к offline | 1–2 нед. | рост нагрузки | F1 live не ниже offline − интервал |
| 8 | Калибровка порога по камере | меньше ложных тревог на конкретной камере | малая | переобучение на камеру | ложных/час ниже при том же recall |
| 9 | Временная модель на последовательности поз вместо ручных признаков | потенциально выше, но | много данных | **при ≈ 200 циклах — переобучится** | только после роста данных в 5–10 раз |
| 10 | Замена Ultralytics (RTMO/RTMDet) | снять лицензионный риск | 1–2 нед. | возможное падение качества | F1 и скорость не хуже в пределах интервала |

Когда **не** делать: пункты 9 и 5 до решения пунктов 1 и 4; любые дорогие модели, пока дешёвые рычаги (данные, вход позы, пороги) не исчерпаны.

## 9. Выпуск и контроль после выпуска

### 9.1. Чек-лист выпуска

- [ ] Нет утечки: пакет классификатора не видел клипов оценки.
- [ ] Прогон оценки без сбоев, профиль тот же, что у выпускаемого пакета.
- [ ] Нижняя граница F1 не ниже заданной; результат подтверждён на отложенной выборке (один раз).
- [ ] Порог события зафиксирован до отложенной выборки (`role=hidden`, `policy=fixed`).
- [ ] `rt_factor ≥ 1.5` на целевом железе (`sd replay`).
- [ ] Ложных тревог в час в пределах договорённого.
- [ ] Классификатор в профиле; режим `live` допустим (`sd solver check … --mode live`).
- [ ] Лицензии: предупреждение Ultralytics (AGPL-3.0) рассмотрено, VideoMAE не используется.
- [ ] PDF прогона, `release.json` с отпечатками и подписью (`SD_RELEASE_KEY`); сборка на чистой машине.

Всё это проверяют ворота («Выпуск»; `sd release`).

### 9.2. После выпуска

1. Решения оператора (подтверждено / ложное) — главный источник новых данных; экспортировать раз в неделю (`sd feedback-export`).
2. Следить: доля ложных тревог, время реакции, доля «не уверен». Рост ложных — признак дрейфа (новая камера, сезон, освещение).
3. Переобучение раз в N недель по накопленным данным: новая версия проходит весь путь с шага 3 раздела 7, включая отложенную выборку.
4. Каждая камера при подключении проходит чек-лист (приложение C).

## Приложение B. Инструкция разметчику (краткая)

1. Смотрите клип целиком, не только кандидатов.
2. **Затяжка** — рука с сигаретой/вейпом поднимается ко рту, пауза 0.5–5 с, отведение. Питьё, телефон, еда, касание лица — отдельные метки, не затяжки.
3. Не уверены — `unsure`/IGNORE, а не догадка. Человек ниже 80 px по высоте — IGNORE.
4. Границы события: от подъёма руки первой затяжки до отведения последней; точность ~1 с.
5. Перед массовыми правками сохраняйте версию. Указывайте своё имя.
6. Не смотрите на подсказки модели, пока ставите метки на контрольных клипах для согласия.

## Приложение C. Чек-лист новой камеры или площадки

- [ ] Рост людей в кадре (`sd eda`): сколько в диапазонах 80–120, 120–200, > 200 px.
- [ ] Ракурс, свет, плотность — записаны.
- [ ] 10–15 минут записи размечены и **не вошли в обучение**.
- [ ] Прогон текущей модели: F1, ложных/час, `rt_factor`.
- [ ] Порог и вход позы выбраны по результату, а не по умолчанию.
- [ ] Включён сбор решений оператора для этой камеры.
- [ ] Данные хранятся локально, срок хранения определён.

## Приложение D. Глоссарий

| термин | значение |
|---|---|
| цикл | жест «рука ко рту → пауза → отвод», найденный автоматом |
| событие | эпизод курения конкретного человека: 2 цикла за 20 с или цикл + прямой признак |
| Event F1 | F1 по событиям организаторов (±3 с, IoU ≥ 0.30) |
| oof | out-of-fold: оценка модели, не видевшей это видео |
| вложенная оценка | порог подбирается внутри обучающей части, а не на проверяемой |
| утечка | пересечение видео обучения и оценки |
| gt_fingerprint | отпечаток разметки, с которой считался прогон |
| отложенная выборка | данные для единственной финальной проверки |
| IGNORE | интервал, который не штрафуется оценкой |
| жёсткий негатив | ложная тревога, подтверждённая оператором |
| серая зона | диапазон оценки цикла, где вызывается VLM |
| `rt_factor` | секунды видео / секунды вычислений; ≥ 1 — успевает в реальном времени |
