## 1. Что это и главные правила

Dev Studio — рабочее место инженера, который улучшает распознавание и пополняет данные. Девять прежних страниц сведены во вкладки в порядке работы:

| вкладка | разделы | для чего |
|---|---|---|
| **Валидация** | Запуск · Результат и PDF · Анализ кэша · Поток | проверить конфигурацию на размеченных папках, получить отчёт (в том числе PDF), найти слабые места, проверить поток |
| **Аналитика** | Журнал · Сравнение подходов · По клипам · Ошибки и порог · Влияние параметров · Классификаторы | сравнивать подходы и прогоны, теги и заметки, влияние параметров |
| **Конструктор** | схема · параметры · Оценить · Сохранить профиль · Серия вариантов | менять архитектуру и параметры с оценкой цены правки |
| **Лаборатория** | Этапы на клипе · Временные ряды · Классификатор · Дообучение · Активное обучение | каждая часть конвейера отдельно, модели по временным рядам, подбор классификатора, дообучение с весами, активное обучение |
| **Задачи** | Разметка событий · Метки жестов · Признаки · Обучение · Результаты · Очередь задач | всё, что улучшает модель: разметка → признаки → обучение → честная оценка |
| **Данные** | Каталог · Проблемы · Версии разметки · Обратная связь оператора · Метки циклов | что есть, где разметка противоречит себе, история и откат разметки, решения оператора → эталон |
| **Модели** | Профили · Реестр · Подключить · Проверить · Перенос · Фото-модель | профили конфигураций и веса |
| **Профилирование** | Скорость по кэшу · Лестница вычислений · Машина | на что способно железо, сколько камер потянет |
| **Выпуск** | Новый выпуск · Выпуски · Установить решатель | единственный путь модели в продукт: ворота качества → решатель + PDF + манифест |

**Три правила, которые держат интерфейс от ошибок:**

1. **Тяжёлое — только фоновой задачей.** Оценка, признаки, диагностика, обучение, варианты, лестница, выпуск запускаются отдельным процессом. Закрытая вкладка работу не теряет, сессия не блокируется. Две тяжёлые задачи на 8 ГБ ОЗУ одновременно не идут: вторая встаёт в очередь. Состояние, прогресс `[i/n]` и журнал видны:
   - в боковой панели;
   - в блоке задач рядом с кнопкой;
   - в разделе «Задачи → Очередь задач» (там же «Стоп» и «Повторить»).
2. **Перед запуском — чек-лист.** Ошибки (⛔) блокируют кнопку, предупреждения (⚠️) видны рядом с ней. Например:
   - нет размеченных клипов;
   - профиль требует CUDA, которой нет;
   - классификатор обучен на клипах оценки;
   - такая конфигурация уже оценивалась;
   - сколько клипов возьмётся из кэша.
3. **Опасное — с подтверждением и с возвратом.** Перезапись пакета, удаление прогона, импорт с заменой, откат разметки, перенос решений оператора идут через диалог. Любая массовая правка разметки сначала сохраняет прежнюю версию (`labels/history`), откат возможен в «Данные → Версии разметки».

В боковой панели задайте **«Кто работает»**: имя пишется в разметку, версии разметки и отчёты.

## 2. Рабочие циклы

### 2.1. Улучшить модель

```
Валидация → Запуск          оценить текущий профиль (чек-лист покажет утечку обучения и кэш)
  ↓
Валидация → Анализ кэша     где ошибки: тепловая карта «клип × метрика», правила слабых мест, видео клипа с циклами
  ↓  (кнопки «Разметить события этого клипа», «Метки жестов клипа»)
Задачи → Метки жестов /     поправить метки (сохраняется версия)
         Разметка событий
  ↓
Задачи → Признаки           источник циклов = прогон оценки; досчитать предмет/фото/VLM; заполненность и сила признаков
  ↓
Задачи → Обучение           спецификация → предупреждения → диагностика (фон) → обучить пакет (фон), при желании подключить к профилю
  ↓
Задачи → Результаты         реестр пакетов (источник, видео обучения, AUC oof) и честная вложенная оценка наборов признаков
  ↓
Аналитика → Сравнение подходов / Влияние параметров   парное сравнение «до / после» на общих клипах, отличия конфигураций
  ↓
Выпуск                      ворота качества → решатель + PDF + release.json
```

### 2.2. Пополнить данные

```
Данные → Каталог      новые видео в data/<папка>; свойства читаются и кэшируются (outputs/catalog/probe.json)
Данные → Проблемы     неразмеченные, конфликт «папка ↔ эталон», затяжки без эталона, дубликаты файлов, нечитаемые видео
  ↓ (кнопка «Открыть разметку»)
Задачи → Разметка событий   подсказки: треки людей (клик по рамке), затяжки из меток жестов; «Следующий неразмеченный»
  ↓
Данные → Версии разметки    зафиксировать версию с комментарием; отличия двух версий; откат
Данные → Обратная связь     решения оператора (подтверждено / ложное) → эталон, с версией до переноса
```

## 3. Что изменено в коде

### 3.1. Новые модули

| модуль | что делает |
|---|---|
| `src/sd/tasks.py` (переписан) + `src/sd/task_wrapper.py` | очередь фоновых задач. `task.json` пишет только интерфейс, `state.json` — только процесс-обёртка: раньше оба писали `task.json`, и это была гонка (аудит A10). Очередь тяжёлых задач (`pump()` вызывают обёртка и просмотр списка, под файловым замком). Прогресс по строкам `[i/n]`. Остановка ожидающей задачи, повтор с теми же значениями. Новые типы задач: `clf_diagnose`, `clf_train`, `report`, `variants`, `release`; у `eval` — классификатор, правки `-s`, роль, порог, «первые N секунд» |
| `src/sd/cli_dev.py` | команды Dev Studio, вынесены из `cli.py`, чтобы не раздувать его (A1): `sd report`, `sd clf diagnose\|train`, `sd release`, `sd variants`, `sd labels list\|snapshot\|restore` |
| `src/sd/reports.py` | PDF-отчёт прогона (matplotlib, без новых зависимостей; кириллица — DejaVu из поставки matplotlib). Разделы: конфигурация и отпечатки, машина прогона, данные, порог, ошибки, клипы, производительность, сравнение с базовым (парный бутстрэп), слабые места, точная команда воспроизведения (все параметры профиля правками `-s`) |
| `src/sd/cache_analysis.py` | «клип × метрика» из кэша без повторного прогона и детерминированные правила слабых мест (`RULES`, 12 штук: мелкие люди, нет циклов, пропуск, чужая рамка, ниже порога, похожий жест по меткам, ложная тревога, конфликт метки папки, точки запястья, медленно, клип в обучении, сбой). | `src/sd/data_catalog.py` | каталог видео (свойства с кэшем), проблемы данных, покрытие по папкам, состояние обратной связи оператора |
| `src/sd/labels_history.py` | версии файлов разметки (эталон событий, метки жестов, метки циклов): снимок только при изменении содержимого, автоснимок не чаще раза в 10 мин, перед массовыми операциями — всегда. | `src/sd/gestures.py` | метки жестов: проверка (неизвестная метка, нет видео или пика, дубль одной затяжки у одного человека) и запись с версией. Заменяет запись из страницы интерфейса с копией в `outputs/backups` |
| `src/sd/release.py` | выпуск. Ворота: прогон без сбоев; F1 ≥ порога; профиль не менялся после оценки (сверка отпечатков); классификатор не обучался на клипах оценки; конвейер собирается; лицензии весов (AGPL и некоммерческие — предупреждение). Дальше решатель, PDF прогона, `release.json` (sha256 архива, HMAC-подпись при заданном `SD_RELEASE_KEY`), проверка выпуска. `--force` выпускает при непройденных воротах, но помечает это в манифесте |

### 3.2. Исправленные конфликтующие модули

### 3.3. Новые команды CLI

| команда | что делает |
|---|---|
| `sd report <прогон> [--baseline <прогон>] [--out файл.pdf]` | PDF-отчёт прогона (по умолчанию в его папке `outputs/experiments/<прогон>/report_<прогон>.pdf`) |
| `sd clf diagnose --spec <имя> [--run <прогон>] [--perm 3] [--no-importance]` | диагностика спецификации → `outputs/classifier/<время>_<спецификация>/` (members, curve, importance, oof, diag.json с предупреждениями) |
| `sd clf train --spec <имя> --bundle <пакет> [--run <прогон>] [--overwrite] [--attach <профиль>]` | пакет по спецификации; ошибки предупреждений (мало данных и т. п.) останавливают обучение |
| `sd release --profile <имя> --run <прогон> [--name …] [--min-f1 0.7] [--with-weights] [--force]` | выпуск в `outputs/releases/<имя>/` |
| `sd variants -d <папка> --base <профиль> --rows variants.json [--policy fixed]` | серия оценок вариантов профиля |
| `sd labels list\|snapshot\|restore` | версии разметки из командной строки |
| `--run <прогон>` у `sd enrich` и `sd oof-eval` | таблица циклов из запусков этого прогона |

## 6. Ограничения и что дальше

- **Цифра качества по-прежнему оптимистична.** Текущие пакеты обучены на тех же клипах, на которых считается F1, и ворота выпуска это показывают. Честная цифра — «Задачи → Результаты → Честная оценка» (вложенная oof). Для поставки нужна отложенная выборка: разметьте `data/custom` и новые клипы, обучите пакет на одних клипах, оцените на других.
- Подпись выпуска — HMAC с общим ключом (`SD_RELEASE_KEY`), а не асимметричная: для передачи внутри команды достаточно, для заказчика нужна асимметричная подпись (нужен пакет `cryptography`, его нет в окружении).
- Аналитика кэша — на pandas: на десятках и сотнях клипов быстро; DuckDB (руководство, раздел 5) понадобится при тысячах.
- Видео-разметчик и плеер вшивают копию видео (до 120 МБ) — длинные 4K-ролики размечайте фрагментами.
- Раздел «Поток» выполняется в процессе интерфейса (интерактивный просмотр тревог). Для длинных роликов используйте `sd replay` фоновой задачей.
- Docker-образ по-прежнему не собирался; профиль GPU не измерялся (без изменений).

## 8. Лаборатория (13 октября)

Вкладка для работы с каждой частью конвейера по отдельности, обучения моделей и активного обучения на реальных данных. Бэкенд: `src/sd/lab.py` (этапы на клипе), `src/sd/tsmodels.py` (временные ряды), `src/sd/active.py` (активное обучение, дообучение); экраны — `src/sd/ui/p_lab.py` и `lab_*.py`. Ничего из лаборатории не пишет в журнал прогонов и эталон событий; единственная запись — метки жестов из «Активного обучения» (с сохранением версии). Результаты пробного `recognize` идут в `outputs/lab/recognize`, чтобы не попадать в таблицы обучения.

### 8.1. Этапы на клипе

Выбирается клип с кэшем позы, запуск позы и профиль. Слева — ручки этапов (ряд d_t, автомат циклов, правила события: `lab.STAGE_KNOBS`), справа пять вкладок:

| вкладка | что видно |
|---|---|
| 1 · Поза и трек | сводка по людям (рост, покрытие, IGNORE), размеченный кадр на любой момент |
| 2 · Ряд d_t | сырой и сглаженный ряд, пороги автомата, найденные (зелёные) и отброшенные (серые, с причиной) циклы, метки жестов |
| 3 · Циклы | таблица циклов с меткой жеста рядом, причины отбрасывания, кадры выбранного цикла по фазам, сравнение с исходной настройкой |
| 4 · Оценка цикла | оценка выбранным классификатором (опционально «без предмета/фото» — быстро, но приблизительно), AUC на размеченных циклах клипа |
| 5 · События | F1 клипа по эталону, TP/FP/FN, дорожки «эталон / система», что изменилось относительно исходной настройки; пороги события пересчитываются мгновенно |

Поза берётся из кэша (её пересчитывает «Конструктор → Оценить»), всё после неё пересчитывается за секунды по хэшам параметров.

### 8.2. Временные ряды

`tsmodels.py`: окно цикла `[начало − отступ, конец + отступ]` приводится к фиксированной длине по каналам (d, скорость, угол локтя, высота кисти, наклон головы …) + два скаляра (длительность, пауза). Модели: `stats` (статистики формы + логрегрессия), `rocket` (случайные свёрточные ядра + логрегрессия), `cnn1d` (маленькая сеть, нужен torch). Честная оценка — фолды по видео или сценам; важность каналов; средние формы по классам; **смесь с табличным классификатором** (кривая AUC от веса рядов). Сохранение — `models/ts/<имя>` без pickle.

На данных проекта (195 размеченных циклов, 31 клип, прогон `20261011_024126_mvp`) рядом дали: `stats` ≈ 0.53–0.55, `rocket` ≈ 0.63–0.67, `cnn1d` ≈ 0.61 AUC против ≈ 0.85 у табличного ансамбля `cycle_mvp` (разброс по сценам широкий, интервал ≈ ±0.1). Смесь с таблицей прироста не дала (0.854 → 0.857). Вывод: форма рядов на этих данных несёт примерно столько же, сколько кинематические признаки, и предмета у рта не заменяет; **в конвейер модели по рядам не встроены** (пакет классификатора не изменён) — лаборатория оценивает их пользу, интеграция имеет смысл только при устойчивом приросте на отложенных видео.

### 8.3. Классификатор

Спецификация собирается из набора признаков, пакета или сохранённой YAML; признаки выбираются списком (заполненность видна), члены ансамбля и их гиперпараметры настраиваются ползунками. Оценка — кросс-валидация по видео/сценам за секунды: AUC с интервалом по видео, AP, ROC и PR всех попыток на одном графике, таблица порогов, калибровка, список самых вопиющих ошибок с кадрами. Спецификацию можно сохранить и поставить диагностику и обучение пакета фоновыми задачами (`clf_diagnose`, `clf_train`).

### 8.4. Дообучение

Берётся спецификация базового пакета; таблица обучается заново на объединённых данных с весами: новые видео (по умолчанию — которых не было в обучении пакета) и «трудные» циклы (out-of-fold ошибка ≥ 0.5) получают больший вес. Сравнение «с весами / без» — по фолдам с отложенными видео/сценами, без весов при оценке; затем сохранение нового пакета (`parent` и параметры дообучения — в манифесте). Веса учитываются логрегрессией и LightGBM; MLP их игнорирует. Колонка `_w` — общий механизм: `bundle` и `classifier` используют её при обучении, если она есть.

На данных проекта усиление трудных циклов **ухудшило** AUC на отложенных видео на ≈ 0.03 — часть «трудных» циклов, вероятно, ошибки разметки; поэтому в «Активном обучении» есть перепроверка меток.

### 8.5. Активное обучение

- **Очередь на разметку:** модель обучается на размеченных циклах, оценивает неразмеченные (пул — любой прогон, например по новой папке) и ранжирует по стратегии (`random`, `uncertainty`, `threshold`, `committee`, `diverse`); у каждой строки — кадры цикла и кнопки меток; метка пишется в `labels/review/gesture_gt.csv` с версией и источником `active`.
- **Перепроверка меток:** размеченные циклы, где out-of-fold оценка сильнее всего расходится с меткой (кандидаты в ошибки разметки).
- **Симуляция:** метки скрываются и «покупаются» по очереди каждой стратегией, качество измеряется на отложенных видео — выбор стратегии и размера пакета по данным, а не по вере. Короткий замер на данных проекта: неопределённость и ансамбль-разброс близки к случайному отбору в пределах разброса (≈ ±0.05–0.1 AUC при ≈ 200 циклах) — различия не доказаны, поэтому стратегия по умолчанию выбирается после симуляции на вашем датасете.
- В прогоне `20261011_024126_mvp` почти все циклы уже размечены (265 циклов, 18 без метки): для практической пользы очередью нужен прогон по новым видео (например, `data/custom`).
