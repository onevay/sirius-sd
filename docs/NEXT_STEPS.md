## Правила, общие для всех шагов
1. **Метки в проекте — мои суждения по кадрам**, а не эталон организаторов (`docs/review/gesture_gt.csv`, `assistant_visual_labels.csv`). Выборки малы (68–130 циклов, 24–29 видео), сцена смешана с классом. Числа отвечают на вопросы «есть ли сигнал» и «что лучше чего»; итоговым качеством они не являются.
2. **Пороги и постобработка замораживаются до скрытого набора** (`configs/default.yaml` + `sd.cmd manifest`); подбор по меткам скрытого набора запрещён регламентом.
3. **Записи с площадки обрабатываются только локально**: не загружать в Colab, Roboflow (в том числе размещённый API «встроенной модели»), Kaggle-ноутбуки, облачные VLM. Публичные датасеты — можно.
4. **Чужие `.pt` (pickle) — только после `sd.cmd models scan <файл>`**; форматы `safetensors` и `onnx` код не исполняют.
5. После каждого шага — строка в [EXPERIMENTS.md](EXPERIMENTS.md) (шаблон — раздел 9).

### A2. Разметка данных из Smoker Detection, Stanford40, Mendeley 2400, CigDet
**Метки готовые**: папки/сплиты (фото) и рамки YOLO (CigDet). Проверить глазами и найти шорткаты:
```bash
sd.cmd photos audit                                                    # дубли (dHash), конфликты меток, «AUC только по метаданным»
```

**Ожидаемый результат.** *Измерено (`outputs/photo/audit.json`):* «Smoker Detection» — 2 пары дублей между train и test (обе «курит»); «Mendeley 2400» — **292 группы почти-дубликатов внутри набора (606 снимков), 1 конфликт меток**; 129 групп пересекаются между наборами (123 «Smoker Detection» ↔ «2400», 6 со Stanford40); классификатор, которому дали только метаданные (размер, яркость, резкость), получает AUC 0.82 / 0.85 / 0.68 (SD / 2400 / Stanford40) — в наборах есть шорткаты (курящие снимки темнее и контрастнее).
**Что делать с этим.** Ничего не удалять: все оценки считаются **по группам дублей** (`xdup_group`), качество проверено внутри страт яркости (0.981–0.997, `eval_brightness_strata.csv`). **Если не так.** Монтаж `smoking` без сигареты у заметной доли снимков → набор непригоден, исключить из `labels.csv` / не класть в `data_external`.

### A3. Проверка классификации «курит / не курит» на фото
```bash
sd.cmd photos export-ov clip && sd.cmd photos export-ov convnext   # один раз: OpenVINO IR (fp16) для встроенной графики; нужны веса: sd.cmd models get clip-vit-b32 convnext-b-in22k

```
**Ожидаемый результат.** *Измерено (`outputs/photo/eval_*.csv`, график `docs/img/photo_eval.png`):* AUC внутри наборов (`clip+convnext:logreg`) — Smoker Detection 0.998, Stanford40 0.982, Mendeley 2400 0.993; перенос на независимый Stanford40 — 0.91–0.93, обратно на «Smoker Detection» 0.97; официальный сплит Stanford40 — AUC 0.977, recall 0.77, доля ложных 0.02 при пороге 0.5; хуже всего «телефон у уха» (0.949); zero-shot CLIP без обучения 0.82–0.93. `photo_v2`: AUC out-of-fold 0.990 (0.998 / 0.991 / 0.965 по наборам). Скорость эмбеддингов на этом ноутбуке: CLIP 0.08 с и ConvNeXt 0.13 с на снимок (в 13–21 раз быстрее torch).
**Как убедиться.** `outputs/photo/eval_within.csv`: строка `clip+convnext:logreg` для «Smoker Detection» ≥ 0.99; `models/photo/photo_v2/manifest.json` содержит `oof_auc` ≈ 0.99.
**Если не так.** AUC ниже ожидаемого на > 0.02 при тех же данных — проверить конвертацию: `sd.cmd photos export-ov clip` (и `convnext`) после экспорта сверяет эмбеддинги OpenVINO и torch на 8 снимках и завершается ошибкой, если средний косинус < 0.99 (измерено: CLIP 0.9975 (минимум 0.9917), ConvNeXt 1.0000 на 8 снимках); тогда `--force` пересоздаёт IR, а `sd.cmd photos embed --backend torch` считает без OpenVINO (медленно).

### A4. Проверка детекции предмета (сигарета/вейп) на фото и на рамках CigDet
```bash
sd.cmd detector-eval smoking_yolo11m_beehzod --photo-sets --per-source 160 --no-box                              # AUC по максимальной уверенности на снимок, recall/FPR при 0.15
sd.cmd detector-eval smoking_yolo26s_basant18 --photo-sets --per-source 160 --no-box
sd.cmd detector-eval smoking_yolo11m_beehzod --photo-sets --per-source 1000 --sources stanford40_actions --no-box   # AUC против каждого трудного негатива
sd.cmd detector-eval smoking_yolo11m_beehzod --data data_external/mendeley/cigdet/data.yaml --split test            # P / R / mAP50 по рамкам
sd.cmd detector-eval smoking_yolo26s_basant18 --data data_external/mendeley/cigdet/data.yaml --split test
```
**Ожидаемый результат.** *Измерено, CigDet, 111 тестовых снимков, `imgsz` 640 (`outputs/analysis/detector_eval_*_cigdet_test.json`):*

| детектор | снимков с детекцией ≥ 0.15 | ≥ 0.5 | P | R | mAP50 | mAP50-95 |
|---|---|---|---|---|---|---|
| smoking_yolo11m_beehzod | 0.93 | 0.91 | 0.57 | 0.53 | 0.46 | 0.12 |
| smoking_yolo26s_basant18 | 0.80 | 0.72 | 0.83 | 0.68 | 0.70 | 0.25 |
| smoke_cig_beehzod_yolo11m | 0.98 | 0.94 | 0.00 | 0.00 | 0.00 | 0.00 |

Beehzod почти всегда реагирует на снимок, но рамки лишь в половине случаев совпадают с сигаретой (IoU ≥ 0.5); basant18 находит реже, но точнее; `smoke_cig_beehzod_yolo11m` срабатывает на каждом снимке мимо сигареты — **отбросить**. *Измерено, фото-наборы при `imgsz` 640 (`detector_eval_<детектор>.json`; в скобках — 416):* Beehzod — AUC 0.939 / 0.911 / 0.905 на Smoker Detection / Mendeley 2400 / Stanford40 (0.946 / 0.891 / 0.900), recall@0.15 0.90 / 0.86 / 0.90, ложных 0.10 / 0.12 / 0.30; basant18 — 0.833 / 0.814 / 0.777 (0.762 / 0.745 / 0.711), recall 0.62 / 0.60 / 0.57 (0.47 / 0.50 / 0.46), ложных 0.01 / 0.03 / 0.09; `smoke_cig_beehzod_yolo11m` — ложных 1.00 / 1.00 / 0.90. **Результат зависит от размера входа (basant18 при 416 занижен), поэтому детекторы сравнивают при одном `imgsz`.**
**Оговорка.** CigDet — крупные стоковые портреты (сигарета в среднем ≈ 18% ширины кадра, 46 px из 250), тот же источник, что положительные снимки «Smoker Detection»; на кропах камер наблюдения (в конвейере детектор работает при `evidence.imgsz = 320`) результат ниже: recall предмета на кропах ваших видео 48–55% (`ANALYSIS.md`, 7.5).
**Что дальше.** На фото размер входа сильно влияет на basant18 (recall +0.10–0.15 при 640 против 416), а в конвейере предмет на кропах считается при `evidence.imgsz = 320`: проверить на кропах — поставить 640 в `configs/default.yaml` и повторить `sd.cmd analyze-cycles --what evidence --detectors smoking_yolo26s_basant18` (гипотеза: recall вырастет; цена ×4 по времени на цикл), затем `sd.cmd feature-auc`.
**Если не так.** Детектор не загружается → `sd.cmd models scan <файл> --details` (вердикт должен быть `ok`); AUC по классам не посчитался на малой выборке (< 15 снимков в классе) → увеличить `--per-source`.

Результат открывается во вкладке «Плеер».
**Как убедиться.** `warnings` в `result.json` пуст (иначе там список признаков, которых не нашлось для пакета); в плеере у цикла с событием красная рамка на таймлайне, а клик по циклу перематывает видео.
**Если не так.** «пакет требует признаков, которых нет» — выбрать пакет «быстрого» набора (`cycle_fast`) или добавить `--objects`; медленно — `sd.cmd resources`.

**D3.4 События против эталона.** ⏳ Эталон и валидатор организаторов не получены. До этого: `sd.cmd event-check` (мои метки; 7 событий — механика). Когда формат придёт: сверить `src/sd/evaluate.py` (копия протокола: ±3 с, пересечение ≥ 1 с, IoU ≥ 0.30 в `peak_sec`, один к одному, IGNORE) с валидатором и заменить; прогнать на dev-наборе; **заморозить пороги и только потом открывать скрытый набор** (чек-лист — раздел 9).

## Блок E. Другая машина и Docker

### E1. Перенос на другой ПК без контейнера
```bash
sd.cmd doctor                       # на новой машине: пакеты против lock-файла, ускорители, веса, пакеты моделей, Ollama
sd.cmd models get all               # веса (нужна сеть); .pt из чужих рук — сначала sd.cmd models scan
```
Пакеты моделей (классификаторы цикла и фото-модели) переносятся zip-экспортом: `sd.cmd ui` → вкладка «Модели» → «Перенос на другую машину» → экспорт; на другой машине тот же раздел → импорт (проверяются пути, расширения, размеры и sha256, запись **атомарна** — при любой ошибке не пишется ничего). Новая модель (например, детектор с другой машины): «Модели» → «Подключить свою модель» (`.pt` сначала сканируется, `.onnx`/`.safetensors` принимаются, запись в `models/user_models.yaml`) → «Проверить модель» (классификатор цикла — AUC с интервалом по видео и список ненайденных признаков; фото-пакет; детектор на своих картинках или кропах циклов; VLM).
**Ожидаемый результат.** `doctor` — все пункты OK (на этом ноутбуке — кроме свободной памяти); для критичных (Python, пакеты, ffmpeg) код возврата 0.

### E2. Docker
```bash
docker compose build
docker compose run --rm cli doctor
docker compose up ui
```
Подробности (тома, офлайн-запуск `--network none`, Ollama без облака, ускорители) — [DOCKER.md](DOCKER.md). **Статус: образ не собирался** (демон Docker на этом ноутбуке не запущен, мало ОЗУ и диска); проверено статически: `docker compose config`, Linux-колёса для всех пакетов (`pip install --dry-run --platform manylinux2014_x86_64`).
**Ожидаемый результат (критерий).** `doctor` в контейнере — OK, кроме «пакеты моделей», «Ollama», «видео данных», пока вы их не примонтировали; `recognize` на одном клипе пишет `result.json` с `warnings: []`. **Если сборка упадёт** — первым подозревать версии колёс `lap`/`openvino` и объём диска; журнал сборки записать в `EXPERIMENTS.md`.

## 9. Что фиксировать после каждого шага и чек-лист перед скрытым набором
Строка в [EXPERIMENTS.md](EXPERIMENTS.md) (формат файла): `| дата | эксперимент | команда | ключевой результат | решение |` — с числами из файла результата, а не из памяти; ошибки и их причины записывайте тоже (так сделаны строки про сбой X-CLIP и про сетку кадров предмета).
**Перед открытием скрытого набора:**
- [ ] пороги цикла, события, серой зоны и оценки цикла записаны в `configs/default.yaml` и `manifest.json` (`sd.cmd manifest`), хеш конфигурации — в `result.json` распознавания;
- [ ] пакеты моделей, которыми будут считать, лежат в `models/cycle`, их sha256 попадают в `result.json`;
- [ ] `sd.cmd doctor` — без красного в критичном; `sd.cmd test` — все тесты проходят;
- [ ] эталон событий и валидатор организаторов получены, `evaluate.py` сверен; на dev-наборе посчитаны P / R / F1 / FP-в-час;
- [ ] записи площадки не покидали этот компьютер (ни одного облачного вызова); машина проверена антивирусом (шаг 0);
- [ ] лицензии всех используемых наборов и весов перечислены в README сдачи (`DATA_AND_WEIGHTS.md`, раздел 4).

## 10. Чего пока нет
Второго разметчика и меток площадки от вас; эталона событий и валидатора; конвертера AVA → события; дообучения детектора и фото-головы на данных площадки; проверки Docker-сборки; снимков «издалека» (80–200 px) — самого близкого к скрытому набору, чего не хватает; сравнения с последовательной нейросетью по скелету (на 68–130 циклах её нечем проверить).
