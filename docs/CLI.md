# CLI: проверка каждой части пайплайна

Запуск (окружение активировать не нужно):

```bash
sd.cmd <команда> [опции]            # из корня проекта, Windows
.venv\Scripts\python -m sd <команда> # то же самое
sd.cmd --help                        # список команд;  sd.cmd <команда> --help — опции
```

Видео можно указывать **путём** или **коротким именем** внутри `data/`: `sm_3`, `5`, `2025_11_06_08_19_11`, либо `video_id` вида `курение__5`.

Общие опции этапов:

| опция | смысл |
|---|---|
| `--start T --end T` | интервал анализа, секунды (на этом CPU считайте окнами по 30–60 с) |
| `-s секция.ключ=значение` | переопределить любой параметр `configs/default.yaml`, можно несколько: `-s cycles.th_in=0.8 -s cycles.th_out=1.1` |
| `--config путь.yaml` | профиль-накладка поверх `default.yaml` (достаточно указать изменяемые ключи; опечатка в имени ключа — ошибка). Готовые: `configs/profiles/fast.yaml` (без RTMPose), `configs/profiles/cpu_torch.yaml` (без Intel-графики) |
| `--force` | пересчитать этап, игнорируя кэш |
| `--video / --no-video` | рендерить ли видео с отметками (H.264, открывается в браузере) |
| `--frame-at 3.3,12.5` | сохранить PNG-скриншоты с отметками на эти моменты — **главный способ проверки глазами** |

Результаты каждого запуска лежат в `outputs/runs/<video_id>/<run_id>/` (имя запуска кодирует интервал, модель, imgsz, рантайм, трекер, fps):

```
pose/        tracks.parquet, keypoints.npy, frame_t.parquet, meta.json   — рамки, 17 точек, время; тайминги
features/<hash>/series.parquet                                           — d_t, скорость, углы, масштаб s по каждому треку
cycles/<hash>/ cycles.parquet, rejected.parquet, states.parquet          — циклы, отброшенные жесты (+причины), состояние автомата
events/<hash>/ events.csv                                                — события в формате организаторов (§10.1 руководства)
evidence/      detections.parquet, crops/*.jpg                           — предмет на кропах кисть–рот
tube/          tube.parquet, strips/*.jpg                                — X-CLIP / VideoMAE по «трубке» человека
render/        pose.mp4, cycles.mp4, *_tXX.png ...                       — видео и скриншоты с отметками
```
`<hash>` зависит от параметров признаков/циклов/событий, поэтому при подборе порогов **поза не пересчитывается** — меняются только дешёвые этапы.

## Что рисуется на видео / кадрах
* рамка человека: `ID3 87% h142px` (ID трека, уверенность детектора, высота в px); серая с `IGNORE` — человек ниже 80 px;
* 17 ключевых точек: цвет = уверенность (красный → жёлтый → зелёный); у носа и запястий подписан процент;
* крест = оценка рта, отрезок запястье–рот, цвет = состояние автомата (REST серый, APPROACH жёлтый, AT_MOUTH красный, RETRACT синий, LONG_HOLD пурпурный), подпись `d=0.31 AT_MOUTH`;
* `cycles:N` — сколько циклов у этого человека закрыто; красная рамка и плашка `SMOKING-LIKE 0.87` на время события;
* жёлтые рамки `cigarette 63%` — детекции предмета (этап `object`); панель с процентами промптов X-CLIP (этап `tube`);
* таймлайн внизу: состояния каждого трека по времени, белые рамки — циклы, красные полосы — события, голубой курсор — текущий момент.

### Этапы пайплайна (каждый можно запустить и посмотреть отдельно)
| этап | команда | пример |
|---|---|---|
| 1. поза + трекинг | `sd.cmd pose <видео> [--model yolo26s-pose --imgsz 960 --runtime torch\|openvino --device cpu\|intel:gpu --tracker botsort\|bytetrack --refine --refine-method rtmpose-s\|rtmpose-m\|yolo]` | `sd.cmd pose sm_3 --start 20 --end 50 --frame-at 30,40` |
| 2. признаки d_t | `sd.cmd features <видео>` | `sd.cmd features sm_3 --start 20 --end 50 --video` |
| 3. циклы жеста | `sd.cmd cycles <видео>` | `sd.cmd cycles sm_3 --start 20 --end 50 -s cycles.th_in=0.8 -s cycles.th_out=1.1` |
| 4. предмет на кропах | `sd.cmd object <видео> [--detector id … --conf 0.15]` | `sd.cmd object sm_3 --start 20 --end 50 --detector smoking_yolo11m_beehzod` |
| 5. видео-модели | `sd.cmd tube <видео> [--models xclip,videomae --tid N --t0 T --t1 T]` | `sd.cmd tube sm_3 --start 20 --end 50 --models xclip` |
| 6. события | `sd.cmd events <видео>` | `sd.cmd events sm_3 --start 20 --end 50` |
| всё сразу | `sd.cmd run <видео>` | `sd.cmd run sm_3 --start 20 --end 50 --frame-at 30` |

Каждая команда использует кэш предыдущих этапов (если для тех же параметров они уже посчитаны), печатает таблицу и пути к артефактам.

**Профили позы.** По умолчанию (`configs/default.yaml`) — «качество»: YOLO26n@960 на встроенной графике Intel через OpenVINO + RTMPose-s для ключевых точек
(≈ 9.5 к/с сквозной, с декодированием). «Быстро»: `-s pose.refine.enabled=false` (≈ 19 к/с инференса). Без Intel-графики: `-s pose.runtime=torch -s pose.device=cpu`.
Первый запуск на новой форме кадра экспортирует модель в OpenVINO (≈ 5 с) и компилирует ядра iGPU (≈ 30 с); дальше — кэш в `models/ov_cache` (первый кадр ≈ 3 с).

| команда | что делает |
|---|---|
| `sd.cmd dataset [--use-weak]` | статистика таблицы циклов: ручные и слабые метки по папкам |
| `sd.cmd train [--use-weak] [--labels файл.csv] [--models] [--vlm файл.parquet]` | LightGBM + `StratifiedGroupKFold` по видео + изотоническая калибровка + абляция групп признаков; бейзлайны (логрегрессия, «только правила»). `--labels` — метки в формате проекта или визуальные (`video,tid,start,label`, как `docs/review/assistant_visual_labels.csv`; они считаются «ручными», хотя это оценка ассистента); `--models` — добавить признаки предмета/X-CLIP/VideoMAE из `outputs/analysis`; `--vlm` — оценка VLM из `sd vlm-eval` (группа G). Печатает таблицу AUC out-of-fold и абляцию, модель и отчёт — в `models/cycle` |
| `sd.cmd ui` | веб-интерфейс (Streamlit): те же этапы с графиками, плюс разметка циклов и обучение; открыть http://localhost:8501 |
| `sd.cmd test` | юнит-тесты |

Подробности подготовки обучения — `docs/TRAINING.md`.

## Веб-интерфейс
`sd.cmd ui` → http://localhost:8501 (`--host 0.0.0.0` нужен только в контейнере). Страницы: **Оценка** (Event F1 по выбранным папкам и профилю моделей), **Просмотр** (видео с эталоном, событиями, рамками, ошибками), **Разметка** (эталон событий на видео), **Модели** (профили, реестр, подключение и проверка), **Этапы** (прежние вкладки по шагам пайплайна и «Распознавание окна»; параметры этапов — в боковой панели этой страницы). Подробно — [AUDIT_AND_CHANGES.md](AUDIT_AND_CHANGES.md), раздел 4.

### Оценка и эталон из командной строки
| команда | что делает |
|---|---|
| `sd.cmd eval -d <папка> [-d …] [-p профиль …]` | события → Event F1 с интервалом, P, R, FP/ч, бюджет ошибок до `--target-f1`, причины ошибок; пишет `outputs/experiments/<время>_<имя>/`. Несколько `-p` — сравнение. `--role hidden` — порог из профиля, подбор запрещён; `--mode clips` — грубая оценка по имени папки |
| `sd.cmd gt [-d <папка>] [--export файл.csv]` | состояние эталона `labels/events_gt.csv`, предупреждения о разметке, экспорт в формате организаторов |
| `sd.cmd gt-from-gestures [--labeler assistant]` | эталон событий `labels/events_gt.csv` из меток жестов `docs/review/gesture_gt.csv`: затяжки одного человека → эпизоды (POSITIVE ≥ 2 затяжек, иначе IGNORE), неясные жесты → IGNORE, папка без курения → «весь клип без курения», клип из папки «курение» без подтверждённых затяжек → IGNORE на весь клип (вне оценки). Строки разметчика `assistant` по этим клипам заменяются, ваши (другой `labeler`) — нет; повтор безопасен |
| `sd.cmd enrich [--objects id,id] [--vlm тег] [--photo-bundle models/photo/<имя>] [--clips …]` | дорогие признаки циклов по готовым запускам `sd recognize` → `outputs/enrich/<клип>/` (предмет на кропах, VLM, фото-модель и zero-shot CLIP); кэш по циклам с отпечатком параметров и весов, прерванный прогон продолжается; `sd recognize` берёт предмет и фото-признаки из этого кэша, если циклы, параметры и веса те же (минуты → секунды) |
| `sd.cmd oof-eval [--sets …] [--kinds lr,gb] [--repeats 3]` | **честная оценка**: оценка каждого цикла моделью, не видевшей его видео (фолды по видео), AUC по классам жестов, F1 события по эталону — лучший на всех клипах (оптимистичен: пороги подобраны на них) и с вложенным подбором порогов (честная оценка процедуры); `outputs/analysis/oof_study.csv` |
| `sd.cmd ladder [--configs n960,m1280,x1280] [--clips …]` | «лестница вычислений»: что даёт более тяжёлая поза (модель, размер входа, уточнение точек) — recall затяжек циклами автомата, лишние циклы, мс на кадр; оценка выигрыша от более мощного ПК; `outputs/analysis/ladder.csv` |
| `python -m sd.run --input <папка\|файл> --out preds.csv [--profile имя] [--roi roi.json] [--render каталог]` | единая команда запуска: `preds.csv` (события выше порога), `preds.all.csv`, `preds.manifest.json` |

* `sd.cmd ui` запускает Streamlit **без наблюдателя файлов**: после правок кода интерфейс нужно перезапустить (иначе в браузере остаётся старая версия страницы, как было при проверке).
* Если порт 8501 занят старым запуском, остановите его или откройте другой порт: `sd.cmd ui --port 8502`.
* Один и тот же интервал видео считается один раз (кэш в `outputs/runs/<видео>/<интервал>_…`); другой интервал или другие параметры позы создают **новый запуск**. При сборке датасета, калибровки и массового анализа из нескольких запусков одного видео с пересекающимися окнами берётся **самый ранний** запуск, более поздние пересекающиеся игнорируются (иначе циклы считались бы дважды, а метки, признаки и оценки VLM привязаны к циклам первого запуска). Поэтому пробные запуски в интерфейсе наборы данных не меняют; чтобы пробный запуск попал в датасет, удалите более ранний пересекающийся запуск из `outputs/runs/<видео>/` или берите непересекающиеся интервалы.

## Типичный цикл проверки части пайплайна
```bash
sd.cmd pose sm_3 --start 20 --end 50 --frame-at 30          # 1) смотрим поза/ID/проценты на кадре (outputs/.../render/pose_t30.png)
sd.cmd cycles sm_3 --start 20 --end 50 --frame-at 33        # 2) циклы: таблица + кадр + таймлайн
sd.cmd cycles sm_3 --start 20 --end 50 -s cycles.th_in=0.8 -s cycles.th_out=1.1   # 3) ослабить пороги и сравнить число циклов
```

## Проверка VLM-верификатора (Ollama)
```bash
sd.cmd ollama up --igpu                     # сервер: 127.0.0.1, без облака, одна модель в памяти; --igpu — встроенная графика (Vulkan), ×2 к скорости
sd.cmd ollama pull qwen3.5:2b-q4_K_M        # модель (≈ 1.9 ГБ); Q8_0-вариант 2b на iGPU не помещается
sd.cmd vlm-bench sm_6 --backend ollama --model qwen3.5:2b-q4_K_M --n 3        # быстрый взгляд: ответ и время на нескольких окнах одного клипа
sd.cmd vlm-eval --per-class 12                                # скрининг на 12+12 размеченных циклах (≈ 6 мин)
sd.cmd vlm-eval --all-cycles --tag full           # все циклы (нужно для event-check); можно прервать и продолжить
sd.cmd feature-auc --vlm outputs/analysis/vlm_qwen3.5_2b-q4_K_M_f6_s224_mouth_full.parquet    # место VLM среди остальных признаков (файлы с суффиксом _vlm)
sd.cmd event-check --vlm outputs/analysis/vlm_qwen3.5_2b-q4_K_M_f6_s224_mouth_full.parquet    # сборка событий против эталона из меток, с оценкой VLM
sd.cmd ollama status                        # установленные и загруженные модели, свободная ОЗУ
sd.cmd ollama down                          # остановить сервер (освободить память); ollama rm <модель> — удалить модель с диска
```
Кадры для модели: `--crop tube` — верх тела человека целиком (сигарета 5–10 px), `--crop mouth` — крупно рот и активная кисть (лучше, см. `ANALYSIS.md`, раздел 8).
