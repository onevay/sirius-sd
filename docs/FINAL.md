# Финальная конфигурация: проверка реализации, исправления, замеры

> 9 октября 2026. Железо: i3-1115G4 (2 ядра / 4 потока), встроенная графика Intel, 7.7 ГБ ОЗУ; во время замеров параллельно работали браузер и приложения пользователя, поэтому скорость — с запасом погрешности ±15 %.
> Метки жестов и событий — суждения ассистента (не эталон организаторов): 31 клип, 23 эпизода курения в 9 клипах. Числа качества — по этим клипам, классификатор обучен на них же (порог фиксирован заранее, но оценка оптимистична; честная вложенная оценка на этих данных 0.74–0.76).

## 1. Итог

Оставлена **одна** конфигурация — профиль `configs/experiments/mvp.yaml` + классификатор `models/cycle/cycle_mvp`:

| часть | значение |
|---|---|
| поза | YOLO26n @960, OpenVINO на встроенной графике |
| уточнение точек | RTMPose-s (CPU) **только у человека с рукой у лица** (`pose.refine.gate_s=3`, +1 с после) |
| частота | **5 к/с** |
| предмет | один детектор Beehzod YOLO11m на OpenVINO (встроенная графика) |
| фото-признак | zero-shot CLIP (OpenVINO), второй backbone не считается |
| классификатор цикла | `cycle_mvp` (логрегрессия ×2 + LightGBM, без калибровки), пороги цикла 0.4 / события 0.55 |

Режим качества — тот же профиль с правками: `-s video.process_fps=10 -s options.cycle_bundle=models/cycle/cycle_mvp10` (в 2 раза медленнее реального времени).

| конфигурация | Event F1 [95 %] | P / R | TP/FP/FN | скорость (× реального времени, установившаяся) |
|---|---|---|---|---|
| **mvp (итог), 5 к/с** | **0.780** [0.67–0.91] | 0.89 / 0.70 | 16/2/7 | 1080p: **1.23–1.33** на трёх клипах без плотных жестов; 0.69 на клипе с 10 циклами за 66 с; 0.54 на 4K HEVC |
| режим качества, 10 к/с | **0.829** [0.74–0.94] | 0.94 / 0.74 | 17/1/6 | 0.29–0.75 |
| прежний mvp (10 к/с, два детектора на CPU) | 0.818 [0.73–0.89] | 0.86 / 0.78 | 18/3/5 | ≈ 0.25–0.4 |

Итоговый прогон `sd eval -p mvp` выполнен после всех правок (до них та же конфигурация давала 0.769 [0.64–0.91]). Что это значит: **реальное время на этом ПК достигается ценой ≈ 0.04–0.05 F1** (меньше циклов находится при 5 к/с: 74 % против 82 % затяжек, см. раздел 3); интервалы перекрываются, различие на 23 эпизодах статистически не доказано. 4K и очень плотные сцены остаются медленнее реального времени.

## 3. Замеры, по которым выбрана конфигурация

**Доля затяжек, найденных автоматом циклов** (131 метка жестов в 17 клипах, `outputs/analysis/ladder*.csv`, `sweep` по кэшу поз):

| частота | с уточнением у всех | с уточнением только у «рука у лица» |
|---|---|---|
| 10 к/с | 107/131 = **82 %** | — |
| ≈ 7.5 к/с (`fps=8`) | — | 99/131 = 76 % |
| 5 к/с | 98/131 = 75 % | 97/131 = **74 %** |

Вывод: ограничение уточнения не стоит качества; потеря — от частоты. Интерполяция ряда до 10 Гц и подбор порогов автомата (`th_in/th_out`, сглаживание, пауза) при 5 к/с цикловую долю не вернули (проверено, из кода убрано). На 4 клипах «лестницы»: без уточнения 13/16, с ним 16/16 — уточнение нужно.

**Детекторы предмета** (AUC цикла, out-of-fold по видео): оба 0.839; только Beehzod 0.837; только basant18 0.790 → оставлен Beehzod.

**Скорость компонентов** (одна и та же модель, тот же результат):

| компонент | было | стало |
|---|---|---|
| детекторы предмета на кропе 320 px | CPU: 346 мс (YOLO11m) + 107 мс | OpenVINO iGPU: 97 + 32 мс |
| признаки предмета на цикл (10 циклов клипа 1) | 8.0 с | 2.4 с (оба), 1.8 с (Beehzod) |
| поза: декодирование | в одном потоке с моделью | отдельный поток (`video_io.prefetch`) |
| оценка потока | заново ряд и автомат для каждого ушедшего человека, каждую секунду | трек, не обновлявшийся дольше `hold_cap+4 с`, пропускается |
| фото-признак | CLIP + ConvNeXt (оценка пакета по кадрам) | только CLIP (нужны лишь `photo_zsd_*`): 0.7 с на цикл |

Не дало выигрыша и убрано: RTMPose на OpenVINO (быстрее в микротесте, медленнее в потоке); предобработка кадра самим cv2 (результат тот же, времени не экономит); аппаратное декодирование (−2 мс на кадр); вход 1280 (дороже в 1.6 раза, на ближних клипах нет выигрыша; на скрытом наборе с дальними камерами проверять отдельно).

**Скорость в потоке** (`sd replay`, окна 66–120 с, `rt_factor_steady`, до последних оптимизаций пропуска ушедших треков и «только CLIP» — они добавлены после замера и должны только ускорять):

| клип | 5 к/с (итог) | 10 к/с |
|---|---|---|
| курение/1 (плотные жесты, 30 к/с) | 0.69 | 0.47 |
| курение/sm_3 (2880×1620 HEVC) | 0.54 | 0.29 |
| лжекурение/2025_11_06_08_13_58 | 1.27 | 0.65 |
| курение/2025_12_08… (100–220 с) | 1.33 | 0.75 |
| лжекурение/noyabrsk_2 | 1.23 | 0.63 |

## 4. Как пользоваться

```bash
python -m sd eval -d data/курение -d data/лжекурение -p mvp --policy fixed         # вся оценка (кэш по клипам)
python -m sd eval -d data/курение -d data/лжекурение -p mvp --clips курение__1,sm_2 # точечная оценка: только эти клипы
python -m sd eval ... -p mvp -s video.process_fps=10 -s options.cycle_bundle=models/cycle/cycle_mvp10   # режим качества
python -m sd replay data/курение/1.mp4 -p mvp                                       # имитация потока: тревоги, F1, задержка, rt_factor
python -m sd.run --input <папка> --profile mvp --out preds.csv
python -m sd train-bundle cycle_new --set obj_hold_zsd --enriched --no-calibrate --kinds lr,gb --runs 5fps --detectors smoking_yolo11m_beehzod
```

`-s ключ=значение` правит профиль на лету (можно несколько раз; `options.*` — опции профиля), `--runs` выбирает запуски одной конфигурации для обучения, `--detectors` задаёт, по каким детекторам считать `obj_any_*`. Те же операции — на страницах «Задачи» и «Классификатор».

В репозитории (не игнорируются git): `configs/experiments/mvp.yaml`, `models/cycle/cycle_mvp`, `models/cycle/cycle_mvp10`, `models/photo/photo_v2`. Веса детекторов и позы скачиваются `sd models get …`. Прежние профили и пакеты убраны в `configs/experiments/archive/` и `models/archive/` (удалять не пришлось; вернуть — переместить обратно).

**GPU-ноутбук (не измерен):** `-s pose.runtime=torch -s pose.device=cuda:0 -s pose.weights=yolo26s-pose -s pose.imgsz=1600 -s pose.refine.device=cuda -s evidence.runtime=torch -s evidence.device=0`, образ — `docker-compose.gpu.yml` (индекс PyTorch `cu126`: для `cu124` нет `torch==2.7.1`).

## 5. Ограничения

* Качество — на 23 эпизодах, размеченных ассистентом; доверительные интервалы широки, 5 к/с против 10 к/с по F1 статистически не различимы, различие 74 % против 82 % по цикловой доле — различимо.
* Установившийся rt_factor ≥ 1 подтверждён на трёх клипах 1080p; плотные сцены (≥ 10 циклов в минуту) и 4K — нет. При нехватке памяти (< 1 ГБ свободно) время фото-признака вырастает в десятки раз: закройте лишнее.
* После последних оптимизаций (пропуск ушедших треков, только CLIP) повторно замерен один клип: курение/1 — 84.9 с вычислений на 66 с видео (0.78 против 0.69), реплей даёт TP 2 / FP 0 / FN 0; остальные клипы не перемерялись; `laptop_cpu` (вход 1280) не оценён: прогон совпал с порчей эталона (п. 2), результат недействителен.
* Docker-образ не собирался на этом ПК; CUDA-конфигурация не измерялась.
* Настоящий поток без исходного файла не считает признаки предмета/фото (нужны кадры файла): в нём годится только быстрый классификатор без предмета.
