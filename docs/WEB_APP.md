# Веб-приложение «Детектор курения» (`sd app`)

Единый интерфейс для оператора и для разработчика модели: карта камер, просмотр видео с выводами модели, профили, передача решателя, источники видео. Стиль — по референсу заказчика (тёмная тема, рейка круглых иконок слева, карточка улицы на карте, кольцевые индикаторы). Работает без Streamlit и без новых зависимостей (стандартный HTTP-сервер + статический фронтенд `src/sd/web/static/`).

```bash
sd.cmd app                  # http://127.0.0.1:8502
sd.cmd app --host 0.0.0.0   # доступ из сети: загрузка файлов и подключение папок отключаются (нет авторизации)
```

## Экраны (рейка слева)

| Значок | Экран | Что делает |
|---|---|---|
| монитор | **Карта** | Вкладки «Все / Активные / Закрытые», период («Последний час … За всё время»), переключатель «Показывать закрытые», фильтр по району, поиск места (улица, район, номер камеры). Светящиеся маячки: красный — тревоги ждут решения, салатовый — норма, серый — нет данных. Клик → **карточка улицы**: активность курения относительно самой активной камеры (в час, %), общее время курения за период, средняя уверенность модели, время реагирования оператора, предупреждение («камера не обрабатывалась», «низкая уверенность модели»), кнопки «Смотреть камеру», «В мультипросмотр», «Тревоги камеры». До 4 камер — мультипросмотр с непрерывным воспроизведением фрагментов |
| ▶ | **Анализ видео** | Видео из папок, загруженные файлы или подключённая папка → профиль или решатель → «▶ Смотреть с анализом» (в реальном времени) или «Всю папку (быстро)». Итог, триггеры, уверенность, люди — см. ниже |
| сетка | **Модели и профили** | Редактор профиля (модель позы, рантайм и устройство, размер входа, трекер, классификатор, фото-модель, VLM, детекторы предмета, fusion, пороги, таблица всех параметров), проверка на этом компьютере, копия / удаление / экспорт YAML; реестр моделей и добавление своей (файл весов или Hugging Face); пакеты классификаторов; **запуск задач доработки** (обучение классификатора, признаки цикла, честная оценка, лестница позы) с журналом |
| самолёт | **Передача и конфигурации** | Упаковка решателя `.sdsolver.zip` (метаданные архитектуры, режимы offline/replay/live, оценка памяти), установка из архива с проверкой целостности, экспорт и импорт профилей YAML, экспорт и импорт пакетов моделей |
| метка (внизу) | **Источники видео** | Подключённые папки (✕ — убрать), «Подключить папку с видео» (путь на этом компьютере), загрузка файлов, формат папок-камер и `cameras.yaml`, каталоги, демо-тревоги |
| колокольчик | **Тревоги** | Список и карточка тревоги (клип/кадр, уверенность, правило), «Подтвердить / Ложная / Не уверен» (клавиши Y/N/U), заметка, фильтры, «Открыть в камере» (фрагмент и момент), журнал решений в CSV |

## Видео любого формата

* **Загрузка и папки:** mp4, avi, mkv, mov, wmv, webm, ts, m4v… Файлы можно перетащить на панель источников; папка подключается по пути и ищется рекурсивно. Загруженные файлы лежат в `data/uploads/`, подключённые папки запоминаются (`outputs/web/roots.json`).
* **Воспроизведение:** формат выбирает браузер (`canPlayType`): H.264/mp4 или VP9/webm. Подходящий исходник отдаётся как есть, остальное один раз перекодируется в `outputs/web_cache` с процентом готовности. Если браузер всё же не принял файл — страница пробует второй формат, затем пишет код ошибки.
* **Везде одинаково:** то же самое для файлов камер, анализа и **клипов тревог**. В интерфейсе разработчика (Streamlit) любой формат проходит через копию `ensure_proxy`; кодек копии — `SD_PROXY_CODEC` (`h264` по умолчанию, `vp8` для браузеров без H.264).

## Анализ видео

**В реальном времени** (по умолчанию): видео и модель идут вместе. Страница получает кадры, циклы и тревоги по мере обработки и сразу рисует рамки людей, красные рамки и плашки уверенности; если модель отстаёт, видео ждёт («Модель отстаёт на N с»). Пока модель загружается, видео не стартует.

После просмотра (и во время него) — вкладки:

* **Итог** — кольца: средняя уверенность по тревогам, время от начала курения до тревоги, скорость (× реального времени, p95 мс/кадр); число тревог и циклов, F1 по разметке (если у клипа есть эталон), вердикт «справляется / не справляется».
* **Триггеры** — *что сработало*: у каждой тревоги правило регламента, число циклов и **оценка каждого цикла** классификатором с отметкой порога; сигналы цикла: пауза у рта, предмет, фото-модель, VLM, поправка fusion и значение до поправки. Ниже — все циклы жеста, прошёл ли цикл порог.
* **Уверенность** — график по времени: точки циклов, отрезки тревог на уровне их уверенности, полоса разметки, пунктир порога цикла и порога события; клик — переход к моменту.
* **Люди** — кто был в кадре (ID, интервал, кадров), циклов, лучшая оценка, тревог.

На видео: рамки (клавиша `B`), плашки «цикл ID n: NN%», «тревога NN%», «разметка: курение». Таймлайн: красное — тревоги, зелёное — разметка, янтарные отметки — циклы. Клавиши: `Пробел`, `←/→` (±5 с), `[` `]` — к соседней тревоге, скорость ×0,5…×4.

## Выбор конфигурации на экране анализа

В списке — профили, установленные решатели и **конфигурации из журнала оценок** (группа «Уже прогонялись»): у каждой видно F1 с доверительным интервалом, precision/recall, число клипов и порог; лучшая по F1 ставится первой. Конфигурация из журнала, у которой с тех пор заменены модели или пакет классификатора, не предлагается (качество относилось бы к другой версии). Копии для браузера (wmv, mkv, H.265) готовятся заранее в фоне при запуске (`SD_WARM_MEDIA=0` отключает).

## Профили, конфигурации и передача

* Профиль — YAML (`configs/experiments/<имя>.yaml`): точечные переопределения конфигурации + options (классификатор, фото-модель, детекторы, VLM, fusion). Опечатка в ключе — ошибка, профиль не портится.
* Проверка «на этом компьютере»: нет CUDA, нет `openvino`, нет пакета классификатора, признаки классификатора не обеспечены — видно сразу в редакторе и на экране анализа.
* **Решатель** переносится на другой компьютер одним архивом (экран «Передача»): метаданные архитектуры, sha256, оценка ресурсов, допустимые режимы. Установка не затирает существующее без явного подтверждения.
* **Доработка модели:** добавить свою модель (реестр), обучить новый пакет классификатора из размеченных циклов (задача `train_bundle`), посчитать признаки (`enrich`), честно оценить (`oof_eval`), проверить на папках (`eval`) — всё запускается и наблюдается на экране «Модели».

## Камеры на карте

Папки-камеры `район-индекс-время` в каталоге потоков (`SD_STREAMS`); положение и название улицы — `cameras.yaml` рядом с папками:

```yaml
gatchina-03: {lat: 59.5762, lon: 30.1291, street: "ул. Соборная", title: "Перекрёсток у вокзала"}
```

Без файла маячки раскладываются условно (в карточке — «положение условное»). Подложка — тёмная карта (Leaflet + CARTO/OSM) при наличии интернета, иначе тёмная схема.

## Методика показателей карточки улицы

| Показатель | Как считается |
|---|---|
| Активность, N / ч | тревог камеры за период / длина периода (для «за всё время» — размах времени тревог) |
| Активность, % | тревог камеры / тревог самой активной камеры за период |
| Общее время курения | сумма длительностей тревог камеры за период |
| Уверенность, средняя | среднее `confidence` тревог камеры |
| Время реагирования | медиана (решение оператора − время поднятия тревоги); «—», пока решений нет |
| Предупреждение | фактическое: нет видео, камера не обрабатывалась воркером, средняя уверенность < 55 % при ≥ 3 тревогах. Данных о погоде и видимости система не имеет и не выдумывает их |

## Безопасность и ограничения

* Сервер слушает `127.0.0.1`. **Аутентификации нет.** На другом адресе привязки загрузка файлов и подключение папок отключены; для сети — только за обратным прокси с авторизацией.
* Файлы вне разрешённых корней (`streams`, `data`, подключённые папки, `SD_WEB_ROOTS`) недоступны (404); артефакты тревог отдаются только из `outputs/`; идентификаторы файлов непрозрачны; загрузка — только расширения видео; веса моделей проходят проверку безопасности (чужой код не исполняется); пакеты решателей проверяются (`..`, sha256, структура).
* В живом режиме не считаются VLM и признаки, которых нет в потоке. Живой поток камер (HLS/WebRTC) не реализован: камеры — папки с фрагментами.
* Реальные модели позы на реальных записях в браузерных проверках не запускались (в среде разработки нет весов/CUDA/OpenVINO): живой режим проверен синтетической позой на настоящих видеофайлах.
