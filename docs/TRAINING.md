# Подготовка обучения классификатора циклов

Классификатор — ядро решения (руководство §4): градиентный бустинг (LightGBM) над вектором признаков **цикла жеста**. Автомат циклов
с мягкими порогами даёт кандидатов (высокий recall), классификатор отвечает «это затяжка?», дальше регламент собирает события.
Здесь описано, что уже подготовлено, и как довести до обучения на настоящих метках.

## Что уже готово (проверено тестами `tests/test_dataset_train.py`)
| часть | где | что делает |
|---|---|---|
| вектор цикла ~40 признаков | `src/sd/dataset.py::cycle_vector` | группы A (кинематика), B (ритм), C (качество наблюдения), F (контекст); пространственное — в ширинах плеч, время — в секундах; пропуски = NaN |
| группы D/E/G (предмет, X-CLIP/VideoMAE, VLM) | `dataset.FEATURE_GROUPS` | колонки зарезервированы; заполняются из `evidence/`, `tube/` по ключу цикла |
| таблица циклов по запускам | `sd.cmd batch`, вкладка «Обучение» в UI | `outputs/dataset/cycles.parquet`, группа = видео |
| метки | `labels/cycle_labels.csv`, вкладка «Разметка» | ключ = видео + момент пика + положение рта (переживает смену порогов) |
| слабые метки по папке | `attach_labels(use_weak=True)` | `лжекурение` → отрицательный, `курение` → «возможно smoke» (шумно!) — **только для проверки конвейера** |
| обучение | `src/sd/train.py`, `sd.cmd train` | LightGBM по параметрам руководства, `StratifiedGroupKFold` по видео, изотоническая калибровка на out-of-fold, монотонные ограничения |
| бейзлайны | `train.py` | логистическая регрессия на A+B; «только правила регламента» (эвристическая оценка паузы) — бустинг обязан их обыграть |
| абляция | `train.py` | убираем по одной группе признаков и смотрим AUC/F1 — готовый слайд «что даёт каждый модуль» |
| оценка событий | `src/sd/evaluate.py` | копия протокола организаторов (±3 с, ≥1 с, IoU ≥ 0.30 в peak_sec, один к одному, IGNORE, FP/час, задержка) с 17 тестами |

## Порядок работы
1. **Кандидаты с мягкими порогами.** Для разметки нужен высокий recall: `sd.cmd batch -s cycles.th_in=0.8 -s cycles.th_out=1.1` (пороги калибруются по данным — см. `ANALYSIS.md`, раздел 7.3).
2. **Разметка** (вкладка «Разметка» в `sd.cmd ui`): по каждому циклу — 8 кадров кропа человека и кнопки `затяжка / питьё / телефон / еда / касание лица / другое / игнор / не уверен`.
   Цель руководства: ≥ 150 положительных и ≥ 300 отрицательных циклов (сложные негативы в приоритете). Двое размечают одни и те же 3–4 клипа и сравнивают.
3. **Признаки D/E** (по желанию, если прошли проверку AUC ≥ 0.80 на сложных негативах): `sd.cmd analyze-cycles` считает предмет на кропах, X-CLIP и VideoMAE по ВСЕМ циклам
   (`outputs/analysis/{evidence,tube_xclip,tube_videomae}_cycles.parquet`, ключ `video, tid, start`), `sd.cmd feature-auc` показывает, какие признаки отделяют курение от ложных жестов
   (на ваших метках вместо визуальных: `--labels labels/cycle_labels.csv`), `dataset.attach_model_features` присоединяет выбранные колонки к вектору цикла. Для одного видео — `sd.cmd object …`, `sd.cmd tube …`.
4. **Обучение**: `sd.cmd train --no-use-weak [--models] [--vlm файл.parquet]` (только ручные метки; `--models` добавляет признаки предмета/X-CLIP/VideoMAE из `outputs/analysis`, `--vlm` — оценку VLM из `sd vlm-eval`, группа G). Проверено на реальных векторах с визуальными метками (раздел 7.7 `ANALYSIS.md`); LightGBM на 45 признаках и 67 циклах проигрывает простой логрегрессии на заранее выбранных признаках — на малой разметке начинайте с простой модели. Результат: `models/cycle/cycle_model.joblib` (модель + калибровка + список признаков), `train_report.json` (AUC/PR-AUC/F1 бустинга, калиброванного, бейзлайнов, важность признаков, абляция), `oof_predictions.csv`.
5. **Порог**: кривая F1/precision/recall/FP-в-час по порогу на out-of-fold предсказаниях, порог — в центре плато, затем в `manifest.json` ДО скрытого набора (`evaluate.threshold_curve`).
6. **Hard negative mining**: прогнать модель по фоновым видео, все ложные срабатывания добавить как негативы, повторить 2–3 раза.

## Правила, которые нельзя нарушать
* **Группировка по видео (актёр+камера+дубль)** — иначе модель запомнит куртку актёра, валидация покажет 0.98. `train.py` отказывается обучаться при < 3 групп.
* **Скрытые данные и контрольные метки** не используются ни для обучения, ни для подбора порога (нарушение дисквалифицирует).
* Слабые метки (папка) не попадают в оценку, если есть ручные: `eval_on` в отчёте показывает, по чему считались метрики.
* Модель на слабых метках помечается `weak_only: true` — для сдачи не годится.

## Что понадобится от вас
* **Время на разметку**: ~300–500 циклов × 3–5 с на цикл ≈ 30–40 минут (интерфейс показывает 8 кадров одним экраном и сохраняет по клику).
* **Свои съёмки** (руководство §9): сверху/издалека, муляж сигареты, вейп, питьё, телефон, еда, касание лица — это главный источник сложных негативов.
* Решение, нужны ли дообученные детекторы сигареты (Roboflow YOLOv8-датасеты, `DATA_AND_WEIGHTS.md`). Дообучение на этом ноутбуке без GPU нецелесообразно — обучайте на Kaggle/Colab **только на публичных датасетах**.

## Ансамбли и безопасные пакеты моделей (этап 3)
* **Наборы признаков заданы заранее** (`src/sd/cycle_models.py`): кинематика (16), ритм (5), положение точек/углы руки/время (19, группа H), предмет (2), видео-модели (5), VLM (1), фото (4). Признаки КЛИПА (`track_len`, `edge_dist`, `overlap_iou`, `brightness`, положение пика в треке, номер цикла) в наборы не входят — они кодируют сцену, а не жест.
* **Сравнить наборы и ансамбли:** `sd.cmd compare-sets [--pool]` — логрегрессия (короткий список и все признаки), LightGBM, MLP и их среднее; фолды по видео, повторные перемешивания, интервал по видео. Выбор набора по этой таблице на 68–130 циклах ненадёжен (разница < 0.05 AUC — шум): ориентир — «чем богаче набор, тем не хуже», решает настоящая разметка.
* **Обучить пакет:** `sd.cmd train-bundle cycle_v1 --set cheap` (без VLM, считается по позе и кропам) и `--set full --vlm …parquet` (с VLM/видео-моделями; для серой зоны). Пакет — каталог `models/cycle/<имя>/` БЕЗ pickle: `manifest.json` (признаки, члены, OOF-метрики, чем обучен), `lgbm_*.txt`, `members.json`, `isotonic.json`. Загрузка и оценка — `src/sd/bundle.py` (проверено тестами: воспроизводимость, пропуски, лишние колонки).
* **Фото-пакет:** `sd.cmd photos train photo_v2` (логрегрессия по эмбеддингам CLIP/ConvNeXt, JSON) — для распознавания на крупных планах; для кропов камер наблюдения перенос слабый (см. `ANALYSIS.md`, раздел 9) — в «дешёвый» пакет по умолчанию не входит.
* **Использование в конвейере:** `sd.cmd recognize … --cycle-bundle models/cycle/cycle_v1 --cycle-bundle-full models/cycle/cycle_full --vlm qwen3.5:2b-q4_K_M --vlm-mode grey` — дешёвый пакет оценивает все циклы, VLM вызывается только в серой зоне, итог берётся из «полного» пакета там, где есть ответ VLM.
* **Нейросеть по последовательности** (1D-CNN/GRU по ключевым точкам) по-прежнему не включена: на 68–130 циклах её нечем проверить; формат пакета допускает добавление (safetensors + JSON-конфиг).

## Нейросеть по скелету (альтернатива, §4.5)
1D-CNN/GRU/ST-GCN по нормированным ключевым точкам окна ±3 с вокруг цикла — выход добавляется как ещё одна колонка вектора (стекинг). На сотнях примеров обычно не обыгрывает бустинг по хорошим признакам; в каркасе не реализована, `keypoints.npy` для неё сохраняются.
