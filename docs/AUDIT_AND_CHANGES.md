## 1. Итог

До изменений в проекте была сильная техническая основа (поза → циклы → события, пакеты моделей без pickle, кэш этапов, копия протокола оценки), но **главную цифру — Event F1 — нельзя было получить из интерфейса**: не было ни разметки событий, ни оценки по выбранным данным, а интерфейс состоял из 15 вкладок этапов с общей боковой панелью на 20 параметров. Теперь:

| было | стало |
|---|---|
| 15 вкладок в одном ряду, параметры всех этапов в общей боковой панели | 5 страниц по ходу работы: **Оценка → Просмотр → Разметка → Модели → Этапы**; параметры этапов только на странице «Этапы» |
| оценки по событиям в интерфейсе нет; `event-check` считал по меткам ассистента | **Оценка** по выбранным папкам: Event F1 с интервалом, P, R, TP/FP/FN, ложные тревоги в час, задержка, бюджет ошибок до целевой F1, кривая порога, причины ошибок |
| разметка = 8 кнопок на цикл + 8 статичных кадров, без видео, без событий | **Видео-разметчик** эталона событий: горячие клавиши, выбор человека кликом по рамке, перемотка и правка |
| плеер без эталона, без ошибок | **Просмотр** с дорожками «эталон» и «ошибки», рамками людей, переходом по ошибкам (`E` / `Shift+E`) |
| модели выбирались в разных местах; нового компонента нельзя было сравнить | **Профиль моделей** (YAML): любой зарегистрированный компонент выбирается из списка; сравнение профилей на одних данных одной кнопкой |
| единой команды запуска из руководства (§10.3) не было | `python -m sd.run --input … --out preds.csv` + `manifest`; `sd eval`, `sd gt` |

### 3.4 Принципы (чтобы не исказить качество)

1. **Алгоритм распознавания не менялся.** Пороги, автомат циклов, сборка событий, веса — как были; обновился только способ их запуска, оценки и просмотра.
2. **Порог не подбирается на скрытых метках.** Роль «скрытый набор» принудительно использует порог из профиля; на валидации выбранный по кривой порог помечается в отчёте как оптимистичный.
3. **Протокол оценки — тот же** (`evaluate.evaluate`: ±3 с, пересечение ≥ 1 с, IoU ≥ 0.30 в `peak_sec`, один к одному, IGNORE). Единственное изменение — исправление ошибки M4, которое делает оценку строже, а не мягче.
4. **Сбой клипа = «событий нет»**, а не «клип исключён»: иначе падающие клипы улучшали бы метрику.
5. **Оцениваются только размеченные клипы** выбранных папок; сколько пропущено — в отчёте. Неразмеченный клип не может тихо считаться «чистым негативом».
6. **Любая модель — через реестр/профиль, без правки кода**; отпечаток профиля включает sha256 весов, поэтому замена весов инвалидирует кэш и попадает в журнал.

## 4. Как этим пользоваться

```bash
sd.cmd ui                     # страницы: Оценка · Просмотр · Разметка · Модели · Этапы
```

**Типовой процесс**

1. **Разметка** → выбрать папки → клип. Перемотать к началу курения → `I`; к концу → `O`; кликнуть по рамке курящего (или нарисовать рамку мышью); `Enter`. Клип без курения — кнопка «Весь клип без курения». Сомнительные участки (малый размер, засветка) — метка «Игнор» (`3`).
2. **Оценка** → папки (по умолчанию все; оцениваются только выбранные и только размеченные клипы) → профиль → «Оценить». Читать сверху вниз: F1 и интервал → «до цели допустимо N ошибок, сейчас M» → кривая порога → клипы → причины ошибок.
3. **Просмотр** — кнопка «Открыть в просмотре» у любой ошибки/клипа; `E` / `Shift+E` — следующая/предыдущая ошибка; кнопка «рамки» включает слой людей.
4. Выбрать порог на **валидации** («центр плато»), сохранить профиль, затем один раз прогнать **скрытый набор** с ролью «скрытый» — порог берётся из профиля.

**Горячие клавиши разметчика:** `Пробел` пауза · `←` `→` кадр (`Shift` — 1 с) · `[` `]` скорость · `I` `O` начало/конец · `P` пик · `1` `2` `3` курение/не курение/игнор · `Enter` сохранить · `Esc` сброс · `Delete` удалить · `N` `B` следующий/предыдущий интервал. На таймлайне: перетаскивание — перемотка, `Shift`+перетаскивание — выделить интервал.

**Модели.** Страница «Оценка» → «Модели и параметры» собирает профиль из списков: поза (любая зарегистрированная, в т. ч. подключённая на странице «Модели»), рантайм/устройство/`imgsz`, уточнение точек, трекер, классификатор цикла, фото-модель, детекторы, VLM (тег из Ollama или вручную). «Сохранить профиль» → `configs/experiments/<имя>.yaml`; «сравнить профили» запускает несколько профилей на тех же данных и сводит в таблицу. Профиль можно писать вручную — формат в шапке `src/sd/profiles.py`.

**CLI**


## 6. Границы

* Это **не** улучшение качества распознавания. Реальную F1 покажет только разметка и прогон на ваших данных — для этого и сделан инструмент.
* Рамка эталона статичная (рамка в `peak_sec`, как в протоколе организаторов): человек, заметно сместившийся за интервал, может не пройти по IoU. Траектории из треков в эталон не подмешиваются сознательно — они зависят от модели.
* Причины ошибок определяются по событиям и эталону; «потерян трек» против «цикл не найден» они не различают (нужны циклы и треки, см. P1-3).
* Слабая оценка «по папкам» — только клип-уровень, без границ и рамок; число — грубая проверка, а не Event F1.
* Интервал бутстрэпа при 2–3 клипах вырожден; отчёт об этом предупреждает.
* Разметчик не хранит траектории рамок и не поддерживает несколько разметчиков одновременно (файл общий, запись атомарная, но без блокировок).

### 7.3 Риски, которые стоит учитывать

* **Переобучение на валидации.** Любой порог/профиль, выбранный по кривой на ≤ 12–20 событиях, оптимистичен. Выбирайте профиль по парному сравнению (P1-7) и фиксируйте один раз.
* **Утечка между клипами одного человека/сцены.** Группировка в обучении уже есть (по видео); в оценке — бутстрэп по клипам. Если один и тот же человек есть в нескольких клипах, интервалы слишком узкие.
* **Расхождение offline и real-time.** Руководство требует, чтобы offline-режим был прогоном онлайн-алгоритма по файлу; сейчас склейка треков идёт постфактум (`stitch_tracks`) — в потоке её не будет, цифры на скрытом наборе нельзя переносить на поток без повторной проверки.
* **Среда.** Все времена и все прежние выводы измерены при работающем майнере на машине автора (`STATE.md`, п. 5); при переносе скорости изменятся.
